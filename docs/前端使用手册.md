## 1. 启动与登录

### 1.1 启动

```bash
# 先打开 Docker Desktop，然后：
cd ~/Desktop/Python/Projectbydate/MiniERP
docker compose up -d          # MySQL + 后端 + 前端
```

- **数据已存在时**，几十秒就能用。**第一次**（或删掉数据卷后）启动，后端会自动建表并用"逐日业务模拟器"生成两年数据，约 11–13 分钟，用 `docker compose logs -f backend` 看进度。
- 前端：**http://localhost:5180**　　后端接口文档（Swagger）：http://localhost:8080/swagger-ui.html
- 数据库：`localhost:3307`，库名 `minierp`，账号密码 `minierp / minierp`（只读演示用）。命令行连库**中文必须加字符集**：`mysql --default-character-set=utf8mb4 ...`，否则中文显示成问号。
- **技术助手（RAG）** 是单独的一套，不在上面的 compose 里：
  ```bash
  cd assistant && docker compose up -d      # Milvus / MongoDB / MinIO / Redis
  uv run python main.py                      # 查询服务 8090 + 导入服务 8091
  ```
  没启动它时，ERP 的其他页面都正常，只有"技术助手"两个页面不可用。

### 1.3 第一次打开：十分钟浏览路线

1. `admin` 登录 → **经营看板**：看当月收入、毛利率（同比）、累计收入、在手订单、应收和逾期；往下是 24 个月收入与毛利率趋势、各系列毛利率、各产线良率、应收账龄、前十大客户、费用结构。
   - 我在 2026-10-05 看到的数字：2026-09 当月收入约 2872.6 万、毛利率 13.8%（去年同期 17.2%）、本年累计 2.47 亿、在手订单约 1866.6 万、应收约 9002.7 万（其中逾期 1523.3 万）。**毛利率比去年同期低，是模拟数据里埋的"铜价上涨"故事**，后面会讲。
2. **销售管理 → 销售订单** → 点任意一行：右侧抽屉打开订单详情（明细、状态、可执行的按钮）。
3. **财务管理 → 记账凭证** → 随便点一张来源是"发货"的凭证：看借贷分录，感受"业务自动生成凭证"。
4. **库存管理 → 现存量**、**批次**：看多仓库和批次。
5. **生产管理 → 高级排产(APS)**：看甘特图和预警。
6. **质量管理 → 批次追溯**：输入一个批次号，做正向 / 反向追溯。
7. 右上角 **待办审批**：进入审批中心。

## 2. 三个版本的自我介绍

### 2.1 30 秒版（电梯）
"我做了一个面向微特电机制造企业的一体化业务系统，覆盖 ERP、PLM、MES、APS、QMS、WMS、SRM、CRM、财务总账、HR、OA 流程、售后和 EHS 等 24 个子系统。它的特点是**业财一体**：销售发货、采购入库、生产报工这些业务动作，会在同一个事务里自动生成会计凭证，总账和库存、应收应付子账能对得上。我还用一个逐日业务模拟器生成了两年的数据，并在里面埋了铜价上涨、客户回款恶化、伺服编码器质量事故等业务故事，作为后面做经营分析 Agent 的数据底座。"

### 2.2 2 分钟版
在 30 秒版基础上补三点：
1. **规模**：38 个后端业务包、229 个接口、127 张表 91 个视图、104 个前端页面入口，113 个单元测试；Java 21 + Spring Boot 3 + Vue 3 + MySQL，Docker Compose 部署。
2. **难点**：多级 BOM 与替代料下的 MRP / APS 齐套排产；实际成本法下的采购价差拆分（按批次在库比例分到存货和成本）；月结和总账子账对账；自研的 OA 流程引擎（条件路由、会签或签、去重）。
3. **AI 部分**：做了一个企业级 RAG 技术助手（LangGraph + Milvus 混合检索 + 重排 + 引用溯源）和 MCP 服务，让 Agent 在沿用调用者权限的前提下读 ERP 数据；写类工具只生成草稿，**不开放审批**。

### 2.3 5 分钟版（带案例）
按"问题 → 方案 → 一个具体案例 → 验证"讲，挑两个案例：
- **案例 A：采购价差**。"实际成本法下，发票价和订单价不同，价差怎么记？我按到货批次**仍在库的比例**拆：在库的部分调整存货成本并重算移动平均价，已经领用的部分进主营业务成本。价差超过 3% 的发票先挂起，财务批准后按审批日的在库比例记账。模拟数据里铜和磁钢按开票月点价，2025 下半年稀土涨价、2026 年铜价上涨，都能在价差报表里看到。"
- **案例 B：伺服编码器虚焊事故**。"2025-11 到 2026-01 我在数据里埋了一次质量事故：L5 产线良率下滑、编码器零位 Cpk 跌破 1、编码器类客诉变多，这几个月生产的伺服现场故障率是平时的 2–3 倍，质量保证金被迫补提。它**横跨 MES、SPC、8D、售后、总账**，可以用来检验一个分析 Agent 能不能把这些线索串起来。"

> 讲完要主动抛一句局限（见第 9 节），例如"成本用的是移动加权平均，没做标准成本差异分析"，这会让听的人更信任你。

## 3. 系统全景：四条主线 + 三个横向能力

### 3.1 四条主线（"从订单到现金"那种端到端链路）

```
① 订单到现金（O2C）   CRM商机 → 销售订单(信用检查) → 发货(扣成品库存、算成本) → 开票(应收) → 收款
                      └ 外销：发货自动生成报关单 → 放行/结关 → 出口退税（免抵退）
② 采购到付款（P2P）   MRP/询价比价 → 采购单 → 到货(待检) → IQC → 入库(应付暂估) → 收票(三单匹配/价差) → 付款
③ 计划到生产（P2M）   MPS/组件工单 → 齐套检查与APS排产 → 下达 → 报工(倒冲领料/替代料) → 完工入库 → 出厂测试/序列号
④ 研发到变更（R2C）   NPI阶段门 → BOM版本 → ECN(四方会签) → 发布 → 生产用BOM更新 → 知识库沉淀
```

### 3.2 三个横向能力
- **财务总账**：所有业务事务内自动出凭证 → 月结 → 总账与子账对账 → 报表（科目余额表、利润表）。
- **组织与流程**：统一身份（账号挂员工，离职即失效）+ 自研 OA 流程引擎（11 个内置流程）+ HR 与计件工资。
- **AI 与开放接口**：技术助手（RAG）、MCP 服务、通用只读查询（白名单视图 + 按角色裁剪敏感列）。

## 4. 前端怎么用：界面通则与 104 个页面逐个说明

### 4.1 界面通则（先记住这几条，100 多个页面都适用）

- **布局**：左侧是按角色裁剪后的菜单（19 个分组）；顶部右侧有"待办审批"、当前部门 · 姓名（角色）、"退出"。
- **列表页**（104 个菜单页里有 78 个都是同一个组件，由 `menu.js` 里的配置生成）：顶部有**关键字搜索**、**下拉筛选**、**日期范围**；底部分页。**点任意一行，右侧滑出 70% 宽的详情抽屉**，里面有该单据的明细和可执行的按钮（按钮会按角色和当前状态显示或隐藏）。
- **没有"导出 Excel"**（见第 9 节）。
- **新建单据**：列表页右上角的蓝色按钮（"新建订单"等），弹出表单；明细行类字段可以增删行。
- **状态驱动**：几乎所有单据都有状态机（草稿 → 确认 → 发货…），按钮只在合法状态下出现；不合法的操作后端会拒绝并给出原因。
- **权限**：菜单隐藏只是第一层，后端每个接口还有 `@PreAuthorize` 校验。销售账号的列表里没有成本、毛利列（后端裁剪）。
- **手写页面**（26 个：看板、树、排产、审批、知识库等）图表可悬停看数值；其余用表格。另有十几个单据详情组件，在列表页的右侧抽屉里打开。

## 5. 九条业务链路的现场演示脚本

> 为了演示顺畅，**第一遍全部用 `admin`**（什么按钮都能点）。想体验权限分离，再按"账号"一栏换号重走一遍。
> 带 ⚠ 的步骤会改动数据（发货、结账等），数据库是演示数据，随便玩；想恢复就按系统说明文档 3.5 重新生成。

### 5.1 订单到现金（O2C）
**账号**：`sales01`（建单、确认）→ `wh01`（发货）→ `fin01`（开票、收款）；或全程 `admin`。
1. **销售管理 → 销售订单 → 新建订单**：选客户、产品、数量，保存为草稿。
2. 点这一行 → **确认订单（信用检查）**。系统会检查客户的信用额度，**超额的订单会冻结在草稿**。可以挑一个回款不好的客户（模拟数据里的 C003，故事 3）试一下，看被拦下的提示。
3. ⚠ 点 **按未发数量发货**：成品库存扣减，成本按移动加权平均计算。多仓库时前置仓整单有货就近发，否则从总仓发（避免拆单）。
4. **销售管理 → 发货单**，点 **开票** 生成应收发票；到 **应收发票** 点 **收款**。
5. **财务管理 → 记账凭证**，按来源筛"发货 / 开票 / 收款"，看每一步自动生成的凭证，借贷合计相等。
**你应该看到**：每一步都有凭证；经营看板的收入、应收随之变化。
**技术讲解讲点**：信用检查（`CreditPolicy`）、发货选仓（`WarehouseRouter`）、移动加权平均（`CostMath`）、业务事务内生成凭证并做借贷平衡校验、不平衡整笔回滚。

### 5.2 采购到付款（P2P）与采购价差
**账号**：`buyer01`（采购）→ `qa01`（检验）→ `fin01`（收票付款）。
1. **采购管理 → 采购订单 → 新建采购单** → **确认下单** → **登记到货（待检）**。
2. **采购管理 → 到货单**，点行 → **来料检验**：抽样不良率 ≤ 2% 合格入库，否则整批判退。入库时按订单价**暂估应付**。
3. 点 **收到发票（生成应付）**：这一步做**三单匹配**（订单价 vs 发票价）。
4. **应付发票**：价差率 ≤ 3% 直接记账；**> 3% 会挂起**，出现 **批准价差 / 驳回**。批准后按"批次仍在库的比例"拆价差。
5. **采购价差** 页面看拆分结果；**付款**。
**技术讲解讲点**：暂估与冲回；价差拆分（在库部分调整存货成本并重算移动平均价，已领用部分进主营业务成本）；3% 容差与审批；模拟数据里铜线、磁钢按开票月点价（故事 1、2）。

### 5.3 计划到生产（含 APS 与 MES）
**账号**：`prod01`。
1. **生产管理 → 生产工单 → 新建工单**，选产品和数量 → **下达**。
2. ⚠ **报工**：按 BOM **倒冲领料**；主料不足时自动用替代料（到 **生产管理 → 替代料使用** 看记录）；良品完工入库，报废损失摊入良品成本。
3. **库存管理 → 库存流水 / 批次**：成品批次号 = 工单号；领料按先进先出。
4. **生产管理 → 高级排产(APS)** → **重新排产**：看甘特图、产线负荷率、"延期、缺料与替代料预警"。
5. **车间看板(MES)**、**产线日报(OEE)**、**安灯**、**首检巡检**、**整机序列号**（伺服每台都有出厂测试记录）。
**技术讲解讲点**：多级 BOM 与低阶码；APS 分层齐套（依次占用主料、替代料、主料在途、替代料在途得到最早齐套日）；下层组件工单的完工日作为上层的"在途供应"；有限产能 + 交期最早优先，缺料工单让位；OEE = 时间开动率 × 性能开动率 × 合格品率。

### 5.4 研发变更（ECN）
**账号**：`eng01` 申请 → `qa01` / `prod01` / `buyer01` / `eng02` 会签。
1. **研发 PLM → 工程变更 ECN → 新建 ECN**，选受影响的产品和变更原因 → 点行 **提交会签**。
2. 切换到其他三个部门的账号，在 ECN 详情里**同意或否决**（**任一否决即否决**；**申请人不能会签**）。
3. 全部同意后批准、发布。发布前能看到**影响分析**（在制工单、库存、成本变化）。
4. **BOM 版本** 页：每个受影响产品出现新版本（A → B），旧版本作废，生产用 BOM 同步更新。
5. **研发协作 → 知识库**：自动多出一页"设计变更说明"。
**技术讲解讲点**：职责分离；BOM 版本号与变更明细计算（`BomChangeCalculator`）；ECN 与 RAG 的联动（编码器压接端子的变更说明会被技术助手检索到）。

### 5.5 客诉 → 8D → RMA → 追溯
**账号**：`qa01`。
1. **质量管理 → 客户投诉(8D) → 登记客诉**，严重度选"中"或"高"。
2. 点 **开始分析**：系统**自动**开 8D 报告、在研发项目里建缺陷、开 RMA 退换货单。
3. **质量管理 → 8D 报告**，点行按 D1–D8 **填写**。
4. 客诉行上点 **追溯**：客诉 → 成品批次 → 原材料批次 → 供应商和 IQC 结果。
5. 点 **8D 关闭**：**必须填根本原因和纠正措施**，否则被拒绝。关闭后研发缺陷同步关闭，经验沉淀为知识库页面。
**技术讲解讲点**：跨模块联动（客诉 → 8D / 缺陷 / RMA / 知识库）；追溯是**批次级**的，原材料批次号 = 到货单号、成品批次号 = 工单号；跨仓调拨时批次随货转移，追溯链不断。

### 5.6 费用报销 → OA 审批 → 预算控制
**账号**：任一员工提交，审批人看路线。
1. **财务管理 → 费用报销 → 提交报销**（选部门、类别、金额）。
2. 进入 **协同办公 → 审批中心 → 我发起的**，点这一条看**审批详情**：顶部是整条**路线步骤条**，下面是时间线。路线在发起时就算好了：条件不满足的节点跳过、申请人本人跳过、前面审批过的人去重。
3. 用路线里下一个审批人的账号登录，在 **待办** 里 **同意 / 驳回（必填理由）/ 转交 / 加签**。**用提交人自己审批会被拒绝。**
4. 金额达到条件会自动出现总经理节点；**超预算**时再加一个"超预算审批（总经理）"节点（先到 **财务管理 → 预算执行** 看执行率）。
5. 审批通过后**自动入账**。
**技术讲解讲点**：流程引擎（JSON 节点、版本、条件表达式 `amount >= 5000 && days > 3 || leaveType == 'SICK'`）；`WorkflowFinishedEvent` 事件解耦；预算控制阈值 90% / 100%。

### 5.7 月结与对账 ⚠
**账号**：`fin01`。
1. **财务管理 → 月结**：看期间列表。选最近一个未结期间点 **结账**。结账前会校验：试算平衡、折旧已计提、增值税已月结、质保金已计提；不满足会报错说明原因。
2. **总账报表 → 总账与子账对账**：存货（1402 / 1403 / 1405 / 1411）、应收、应付、暂估、固定资产、质保金等逐项对比，差异应为 0（存货有约万分之 0.2 的舍入差，页面会展示）。
3. **科目余额表、利润表**：营业收入 = 主营 + 其他业务收入；另列税金及附加、销售 / 管理 / 研发 / 财务费用。
4. **反结账**只对**最后一个已结期间**可用，会删除该期的结转凭证；演示完再结回去。
**技术讲解讲点**：期间必须顺序结账、已结期间禁止记账；结转制造费用差异和损益；对账是"不变量"校验，是整个业财一体设计的验收手段。

### 5.8 售后：保修查询 → 服务工单 → RMA
**账号**：`sales01` 或 `admin`。
1. **生产管理 → 整机序列号**，复制一个伺服序列号。
2. **售后服务 → 售后看板** 顶部 **保修查询**：粘贴序列号 **查询**，看产品、生产工单、出厂测试、客户、发货日期、**保修到期日**（伺服 18 个月，其他 12 个月）、是否在保、历史工单。
3. **服务工单 → 新建工单**：优先级决定 SLA（P1 客户停线 7×24，响应 2 小时 / 解决 24 小时；P2、P3 按工作日 8:30–17:30 计时）。
4. **RMA 退换货 → 收货**；**质量保证金** 看预计负债的计提和冲减。
**技术讲解讲点**：`SlaClock` 跳过周末和法定节假日；换新时成品库存不足退货量 3 倍就改为维修；保证金年末按近 12 个月索赔测算补提或冲回。

### 5.9 技术助手（RAG）
**前置**：先启动 `assistant`（见 1.1）。
1. **技术助手 → 知识库管理** → **同步 PLM 文档**（等任务完成）。
2. **产品技术问答** 里依次问：

## 6. 技术深挖：十二个设计决策

每一条按"做了什么 / 为什么 / 取舍 / 容易被追问什么"写。

### 6.1 业务规则抽成纯函数类
- **做了什么**：`CostMath`（移动加权平均）、`BomExploder`（多级 BOM 展开）、`ApsScheduler`、`KittingCalculator`、`IncomeTaxCalculator`、`PayrollCalculator`、`SpcCalculator`、`ExportRefundCalculator`、`TouTariff`、`SlaClock` 等，**不依赖 Spring 和数据库**；服务层只负责读写数据和编排。
- **为什么**：这些是最容易出错的业务逻辑，写成纯函数就能直接做单元测试，113 个测试主要覆盖它们。
- **取舍**：类多，参数传递多；规则被拆开后，要看懂一个业务得在服务层和计算类之间来回跳。
- **追问**：*"为什么不用领域模型 / DDD？"* → 这是务实选择：规则集中在无状态的计算类里，聚合边界没有那么复杂，先保证可测。

### 6.2 业财一体：事务内生成凭证
- **做了什么**：发货、开票、收款、入库、收票、付款、报工、报销、调拨、折旧、工资、增值税、售后等，都在**业务事务内**调用 `GlService.post`；先经 `VoucherValidator` 校验借贷平衡，不平衡则**整笔业务回滚**（共 181 处 `@Transactional`）。
- **为什么**：业务和财务的数据要么一起成功要么一起失败，否则总账与子账会对不上。
- **验证**：31,241 张凭证全部借贷平衡；24 个期间已结账；总账收入、应收与销售发票子账分文不差；存货总账与子账差约万分之 0.2（移动平均单价舍入）。
- **取舍**：同步生成凭证让业务接口变慢、耦合更紧；换来强一致。
- **追问**：*"并发下怎么保证？"* → 诚实回答：单机 MySQL，依赖数据库事务；模拟器是单线程逐日跑；没有做并发压测，高并发场景是后续改进项（见第 9 节）。

### 6.3 成本：移动加权平均，每个仓独立核算
- **做了什么**：每个仓库独立维护现存量和平均成本；调拨发出 Dr 1402 调拨在途 / Cr 存货，到货反向。批次、库位也按仓库管理。
- **为什么**：在途期间货物不在任何仓库，需要科目承接，这样总账和库存账始终对得上。
- **取舍**：实际成本法，**没有标准成本和差异分析**（价格差异 / 用量差异），这是已知限制。

### 6.4 采购价差拆分
- **做了什么**：价差 = 发票金额 − 暂估金额；按到货批次**仍在库的比例**拆：在库部分调整存货成本（1403）并重算移动平均价，已领用部分计入主营业务成本（6401）。> 3% 的发票先挂起，财务批准后按**审批日**的在库比例记账；驳回则作废等供应商重开。
- **为什么**：实际成本法下，这是让存货和成本都准确的做法；拆分比例直接取自批次数据，不是估算。

### 6.5 多级 BOM、MRP 与 APS
- **做了什么**：`BomExploder` 逐层展开、同料合并、算低阶码、检测循环引用。MRP 按"在制需求（展开到外购件）+ 10 天安全库存 − 库存 − 在途"生成采购；APS 按低阶码分层排产，每层先齐套检查再排有限产能（单班产能 × 班次，交期最早优先，缺料让位）。
- **为什么**：伺服是三层结构（转子铁芯 → 转子/定子组件 → 成品），必须逐层计算，上层的开工要等下层完工。
- **取舍 / 已知限制**：**MRP 与 APS 还没合并成一次计算**——组件工单由 MRP 下达，APS 只排程。

### 6.6 自研 OA 流程引擎
- **做了什么**：流程定义用 JSON 描述节点，按版本管理，运行中的实例按发起时的版本执行；`WorkflowRouter` 在**发起时**算出整条路线（条件不满足的节点跳过、申请人本人跳过、前序审批过的人去重）；条件表达式由自研的 `ConditionEvaluator` 解析；办理操作有同意、驳回、转交、加签、撤回。
- **为什么自研**：要和组织架构（直属上级、部门负责人）和业务事件深度耦合；条件表达式**不用脚本引擎**，避免表达式注入。
- **集成方式**：流程结束时在**同一事务内**发布 `WorkflowFinishedEvent`，报销、请假、资本性支出、合同、IT 变更、作业票等模块各自监听。
- **取舍**：同事务发布让一致性好（业务动作失败，审批一起回滚），代价是监听方慢会拖住审批。
- **追问**：*"为什么不用 Flowable / Activiti？"* → 它们功能全但重，BPMN 建模对这里的"条件路由 + 去重 + 与组织架构耦合"并不省事；自研只实现需要的子集（没有并行网关、子流程）。

### 6.7 认证与权限
- **做了什么**：BCrypt + JWT（12 小时）；每个 Controller 用 `@PreAuthorize` 限角色；通用只读查询走白名单视图，按角色裁剪成本、毛利、工资列（`ViewRegistry.sensitiveCols`）；审批人不能审批本人单据；`@Audited` 切面写审计日志。
- **离职即失效**：`JwtAuthFilter` 每次请求检查账号是否启用，`UserStatusCache` 缓存 60 秒，所以旧令牌最多 60 秒后失效。
- **取舍**：缓存 60 秒是性能和及时性的折中；JWT 本身无状态，不能主动吊销，靠"账号状态检查"补。
- **没有做**：登录失败锁定、密码复杂度策略、令牌刷新（见第 9 节，讲解时别说做了）。

### 6.8 配置驱动的前端
- **做了什么**：`menu.js`（1,521 行）用配置描述菜单、列、筛选、按钮（含角色和显示条件）、表单；104 个菜单页里 78 个列表页共用 `ListPage` + `ViewTable` + `FormDialog`；复杂的 26 个页面（看板、树、排产、审批、知识库）手写，另有十几个单据详情组件。
- **为什么**：新增一个列表页只加配置，不用写 Vue 代码；菜单和路由由同一份配置生成，权限（`roles`）只写一处。
- **取舍**：配置文件越来越大；复杂交互仍要手写页面；没有前端自动化测试。

### 6.9 逐日业务模拟器
- **做了什么**：`BusinessSimulator` 逐个工作日调度 HR、Ops、Dev、Fin、Svc、Ehs、Plm 等子模拟，**每一笔数据都通过真实的业务服务生成**（不是直接往表里插），所以库存、成本、应收、应付、总账互相勾稽；并埋入 24 个业务故事。
- **为什么**：做经营分析 Agent 需要"有答案的数据"；没有真实企业数据，又想保证内部一致，只能让业务服务自己跑出来。
- **取舍**：数据是合成的，分布做了简化；首次启动要 11–13 分钟。
- **追问**：*"数据是真的吗？"* → 不是，客户、供应商都是虚构的，README 里写明；它的价值是**内部一致 + 可验证的故事**。

### 6.10 测试与验证
- **现状**：31 个测试类、113 个单元测试，**全是纯函数测试**（无 Spring 集成测试、无前端自动化测试）。
- **另一层验证**：每次重新生成数据后做**数据一致性检查**（凭证全部平衡、总账对子账、增值税科目期末为 0）；RAG 有 48 题的评测集。
- **怎么说**："规则层靠单元测试，跨模块的一致性靠数据层的不变量校验。集成测试和端到端测试是我知道缺的部分。"

### 6.11 RAG 技术助手与 MCP
- **导入图（LangGraph）**：PDF 经 MinerU 转 Markdown → 视觉模型理解图片 → 标题语义切分 + 递归细切（父子两级）→ 识别型号 → 父章节存 MySQL / Redis → BGE-M3 稠密 + 稀疏向量 → 写入 Milvus（按 `doc_key` 幂等替换）。
- **查询图（LangGraph）**：问题改写与型号对齐（结合 MongoDB 历史，有歧义才反问）→ 并行：混合检索、HyDE、联网搜索（MCP）、ERP 实时数据 → 加权 RRF → bge-reranker 重排 + 动态 TopK + 父文档扩展 → 带引用生成（SSE 流式）。
- **关键设计**：子块检索、父章节回答；子块带"文档标题 + 章节"上下文头（31 份规格书结构相同，不加会串型号）；ERP 数据**参数化只读查询**，不执行模型生成的 SQL；BOM 版本、ECN 状态以 ERP 为准。
- **MCP**：38 个工具；**网关模式**，沿用调用者本人的 JWT 和角色；写类工具只生成草稿或发起申请，**不开放任何审批工具**。
- **评估**：48 条自动生成的评测集，检索 Hit@5 0.972；完整链路答案准确率 0.958，平均 7.3 秒。**局限**：评测集由系统自动生成、题量小，不代表真实用户问题分布。

### 6.12 可观测性与运维
- **做了什么**：SLF4J + Logback，`TraceIdFilter` 把追踪号写入 MDC 并随响应返回，按天滚动；Swagger 文档；Flyway 管结构（`ddl-auto: validate`）；Docker Compose 部署。
- **没做**：Prometheus / Grafana 指标和告警；ERP 侧的缓存层、集群、读写分离；技术助手进程容器化（现在是宿主机进程，重启后要手动拉起）。

## 7. 技术讲解问答 60 题

> 每个回答都控制在能在 30–60 秒讲完的长度。**先给结论，再给一个具体例子，最后（如果被追问）讲取舍和局限**。
> 标 ★ 的是最容易被问到的。

### A. 总览与定位

**1. ★ 这个项目是什么，解决什么问题？**
一个面向微特电机制造企业的一体化业务系统，覆盖 ERP、PLM、MES、APS、QMS、WMS、SRM、CRM、财务总账、HR、OA、售后、EHS 等 24 个子系统。核心思路是**业财一体**：业务动作在同一个事务里自动生成凭证，总账和各子账能对上。同时它有一个逐日业务模拟器，生成两年带"业务故事"的数据，作为后面做经营分析 Agent 的数据底座。

**2. 为什么选微特电机制造这个场景？**
制造业的业务链最长、约束最多：多级 BOM、替代料、批次追溯、质量闭环、出口退税，每一块都能做出和真实业务一致的规则；而且我有审计和金融风控的背景，对"凭证要平、对账要对上"比较敏感。另外我在科朗（微电机企业）做过 AI 项目，对这个行业的产品和流程有接触。

**3. ★ 这是你一个人做的吗？代码是你写的吗？**
*（按你的真实情况回答，别夸大。）* 建议这样说：业务范围、模块拆分、规则取舍和验收标准是我定的，代码主要借助 AI 编码工具（Claude Code）完成。我逐模块验收，数据一致性用 SQL 校验（凭证平衡、总账对子账），关键业务规则我能讲清楚为什么这么设计，也能自己改。——**不要说成"我纯手写了 2 万行 Java"**，技术讲解官只要让你现场改一个规则就会露馅。

**4. 和 SAP、金蝶、用友有什么区别？**
它不是替代品，规模和成熟度差几个数量级。区别在于它是**一个可以完整读懂的闭环**：每个模块都有明确的规则和可验证的结果，适合学习、演示和做分析 Agent 的实验场；真实 ERP 要处理的多组织、多账簿、高并发、合规认证它都没做。

**5. 项目规模有多大？**
38 个后端业务包、35 个控制器、229 个 REST 接口、约 1.99 万行 Java；127 张表 + 91 个视图，12 个 Flyway 迁移；前端 19 个菜单组、104 个页面入口；113 个单元测试；38 个 MCP 工具；模拟数据 3.1 万张凭证、17.5 万台伺服序列号。

**6. 最难的部分是什么？**
我会挑**采购价差的拆分**和**多级 BOM 下的 APS 齐套**。前者要在实际成本法下同时保证存货、成本和总账正确；后者要把下层组件的完工日传给上层作为"在途供应"，还要让缺料工单让位。

**7. 有真实用户吗？上线了吗？**
没有，是本地 Docker Compose 部署的演示系统，数据是模拟生成的，客户和供应商都是虚构的。它的价值在于业务规则的完整性和内部一致性，而不是真实使用。

**8. 为什么要做这么大？**
两个目的：一是作为我转 AI 工程的作品集，能展示对制造业务的理解；二是给"财务经营分析 Agent"准备一个**有标准答案的数据环境**——数据里埋了铜价上涨、客户回款恶化、编码器质量事故等故事，可以用来检验 Agent 能不能做对毛利归因。

### B. 架构与技术选型

**9. ★ 整体架构是什么样的？**
浏览器（Vue 3）→ Nginx（静态资源 + `/api` 反向代理到后端；`/assistant-api`、`/kb-api` 转发到宿主机上的技术助手）→ Spring Boot 后端 → MySQL。技术助手是独立的 Python 服务（FastAPI + LangGraph），自己有 Milvus、MongoDB、MinIO、Redis；它通过只读账号查 ERP 实时数据，通过 MCP 网关调用 ERP 接口。

**10. 为什么选 Spring Boot + Vue？**
Java 在企业系统里最常见，Spring 的事务、安全、AOP 对"业务 + 财务"这种强一致场景很合适；Vue 3 + Element Plus 做后台管理界面效率高。

**11. 为什么 JPA 和 JdbcTemplate 混用？**
简单实体的增删改用 JPA；报表、批量操作和复杂联表用 JdbcTemplate 写 SQL，更直观也更好调优。

**12. Flyway 的作用？`ddl-auto: validate` 是什么意思？**
Flyway 用版本化脚本管理表结构（V1–V12），环境之间结构一致；`validate` 表示 Hibernate 只校验实体和表是否匹配，不自动改表，避免意外改库。

**13. 为什么是单体而不是微服务？**
业务之间强事务依赖（发货要同时动库存、成本、凭证），拆成微服务就要面对分布式事务；这个规模单体更简单、更一致。模块边界用包划分，流程结束用领域事件解耦，将来要拆也有边界可循。

**14. 为什么前端做成配置驱动？**
104 个菜单页里有 78 个是"列表 + 筛选 + 详情抽屉 + 几个按钮"，用一份 `menu.js` 配置生成，新增页面只加配置；菜单、路由、权限来自同一份配置，不会出现"菜单隐藏了但路由还能进"。复杂的 26 个页面（看板、排产、审批等）手写。

**15. Nginx 在里面做什么？**
前端容器里的 Nginx 提供静态资源，并把 `/api/` 反向代理到后端，`/assistant-api/`、`/kb-api/` 转发到技术助手，浏览器只需要访问一个端口 5180。

**16. 怎么扩展到更大规模？**
诚实回答：现在是单机。第一步加 ERP 侧的缓存、给报表建汇总表或读库；第二步把耗时任务（月结、MRP、APS）异步化；再往后按业务域拆服务。我还没做过这些，是改进方向。

### C. 财务与业财一体

**17. ★ "业财一体"具体怎么实现？**
业务服务在自己的事务里调用 `GlService.post` 生成凭证。比如发货：事务里扣库存、算成本、写发货单，同时记收入和成本凭证。凭证先过 `VoucherValidator` 校验借贷平衡，不平衡就抛异常，**整笔业务回滚**。所以总账和业务数据不会出现一边成功一边失败。

**18. 凭证借贷不平衡怎么办？**
不会落库：校验在事务内，失败就回滚并返回错误。验证结果是 31,241 张凭证全部平衡。

**19. 为什么用移动加权平均？为什么不用先进先出或标准成本？**
移动加权平均实现简单、符合很多制造企业做法，每次入库重算单价。先进先出在批次层面也有（出库按批次先进先出消耗，用于追溯），但成本核算用移动平均。**标准成本和差异分析没做**，这是已知限制。

**20. ★ 采购价差怎么处理？**
发票价和订单价不同，价差 = 发票金额 − 暂估金额。按到货批次**仍在库的比例**拆：在库的部分调整存货成本（1403）并重算移动平均价；已领用的部分计入主营业务成本（6401）。价差率超过 3% 先挂起，财务批准后按审批日的在库比例记账，驳回则作废等供应商重开。

**21. 应付暂估是什么？为什么需要？**
货到了但发票没到，会计上要先确认负债，入库时按订单价贷记"应付账款-暂估"；收到发票时冲回暂估，再确认正式应付（价税合计）。这样存货和应付在收货时点就是准确的。

**22. 月结做了什么？**
结账前校验：试算平衡、折旧已计提、增值税已月结、质保金已计提；然后结转制造费用差异到主营业务成本，结转损益到本年利润，12 月再转入未分配利润。期间必须顺序结账，已结期间禁止记账；反结账只能从最后一个已结期间开始。

**23. 总账与子账对账是什么？**
总账科目余额要等于对应子账合计，比如存货总账对库存子账、应收对销售发票、应付对采购发票、固定资产对资产卡片、质保金对台账。它是整个业财一体的**验收手段**：只要有一个业务忘了生成凭证或金额不对，对账就会显示差异。存货有约万分之 0.2 的差，来自移动平均单价舍入，页面会展示。

**24. 出口退税免抵退怎么算？**
按生产企业免抵退税口径：先算不得免征和抵扣税额并做进项转出；再算应纳税额和免抵退税额；拆成应退税额和免抵税额，剩余是期末留抵；各增值税明细科目结转到未交增值税；城建税、教育费附加按（应纳 + 免抵税额）的 12% 计提。次月 15 日缴税，退税款约 60 天到账。

**25. 计件工资和个税怎么算？**
各产线计件单价按报工日期取有效单价，只计良品；班组当月计件总额按组员出勤工时分摊，用**最大余数法**处理分摊尾差。月工资里月薪按在职天数折算，扣事假旷工，计件不足保底的补足；社保公积金按基数上下限；个税用**累计预扣法**。

**26. 固定资产折旧怎么做？**
支持年限平均法和双倍余额递减法（最后两年改直线法）；当月增加次月起提，当月减少当月照提；按"计划累计 − 已提累计"算每月金额，所以舍入误差不累积；折旧按使用部门分别计入制造、销售、管理或研发费用。

**27. 质量保证金是什么？**
售后的预计负债（科目 2801）：每月按主营收入乘以计提比例计提，保内成本和客户索赔冲减；年末按近 12 个月索赔测算应有余额，补提或冲回，并确定下年计提比例。

### D. 供应链与生产

**28. 多仓库调拨怎么保证对账？**
发出时 Dr 1402 调拨在途 / Cr 存货，到货时反向。在途期间货物不在任何仓库，由 1402 承接，所以总账与库存账始终对得上；批次随货转移，追溯链不断。

**29. ★ 批次追溯怎么做？**
原材料批次号 = 到货单号，成品批次号 = 工单号，出库按先进先出消耗批次。**反向**：客诉 → 成品批次 → 原材料批次 → 供应商和 IQC 结果；**正向**：原材料批次 → 工单 → 发货单 → 客户，得到召回清单。多级 BOM 下逐层展开。

**30. MRP 怎么算采购需求？**
按"在制工单需求（展开到外购件）+ 10 天安全库存 − 库存 − 在途"生成采购单。

**31. ★ APS 怎么排产？**
按低阶码分层。每层先做齐套检查，得到最早齐套日；下层组件工单的计划完工日当作上层的"在途供应"；有限产能按"单班产能 × 班次"，交期最早优先（EDD），缺料工单让位给已齐套的工单。输出甘特图、负荷率、延期 / 缺料 / 替代料预警。

**32. 齐套检查具体怎么做？**
依次占用：主料现存量 → 替代料现存量 → 主料在途 → 替代料在途，得到最早齐套日（`KittingCalculator`）。

**33. 替代料怎么处理？**
替代料按优先级和替代比例配置（例如铜线换铜包铝，按重量折算）。报工倒冲时主料不足会自动用替代料，并记录主料数量和替代料耗用，可以在"替代料使用"页看到；APS 齐套也会考虑替代料。

**34. OEE 怎么算？**
时间开动率 × 性能开动率 × 合格品率，按产线每天结算。设备停机会按设备的"停机损失比例"压低当天产量，所以设备故障会传导到交付和 OEE。

**35. 倒冲领料是什么？**
报工时按 BOM 自动扣减原材料，而不是工人逐笔领料。优点是减少录入，缺点是库存账依赖 BOM 准确——所以 ECN 发布要同步更新生产用 BOM。

**36. WMS 的上架和拣货规则？**
入库上架：同一物料集中存放，新物料放最空的库位（`BinAllocator`）；出库拣货先拣零散库位。Σ库位库存 = 仓库现存量，可以一键校验账实一致。

**37. 前置仓怎么补货？**
订货点法：可用量低于 7 天需求就补到 14 天（`ReplenishmentCalculator`），可以一键生成调拨单。

### E. 质量与研发

**38. 客诉、8D、RMA 是怎么联动的？**
中高严重度客诉进入分析时，自动开 8D、在研发项目里建缺陷、开 RMA；8D 结案时同步关闭缺陷并把经验沉淀到知识库。关闭客诉前必须填写根本原因和纠正措施。

**39. SPC 怎么做？**
均值-极差控制图，计算 Cp / Cpk / Ppk，按 Western Electric 规则判异。数据里编码器零位的 Cpk 在虚焊事故期间跌破 1，可以在图上看到。

**40. PFMEA 的 RPN 是什么？**
RPN = 严重度 S × 频度 O × 探测度 D，用来确定措施优先级，并记录改进后的 RPN。

**41. 出货检验的抽样怎么定？**
按 GB/T 2828.1 一般检验水平 II、正常一次抽样，含箭头规则，根据批量查字码得出样本量和接收数 Ac。

**42. ★ ECN 流程怎么设计？**
草稿 → 提交会签（研发、生产、质量、采购四方，任一否决即否决，申请人不能会签）→ 批准 → 发布。发布前做影响分析（在制工单、库存、成本变化）；发布时每个受影响产品生成新 BOM 版本（A→B），旧版本作废，生产用 BOM 同步更新，并自动生成知识库的设计变更说明。

**43. NPI 阶段门是什么？**
新产品开发的评审机制：概念 → 设计 → 样机 → 试产 → 量产，每个阶段门评审结果是 GO / HOLD / KILL。立项会自动建研发项目。

### F. 流程、权限与安全

**44. ★ OA 流程引擎怎么设计的？**
流程定义用 JSON 描述节点，按版本管理，运行中的实例按发起时的版本执行；审批人类型有直属上级、部门负责人、指定部门、角色、指定账号；节点可设或签 / 会签和进入条件表达式；发起时由 `WorkflowRouter` 算出整条路线（条件不满足的跳过、申请人本人跳过、前序审批过的人去重）；流程结束发布 `WorkflowFinishedEvent`，业务模块监听后执行入账、写考勤、建卡等。

**45. 为什么不用 Flowable？**
它功能完整但重，BPMN 建模对"条件路由 + 去重 + 与组织架构耦合"的需求并不省事；自研只实现需要的子集。代价是**没有并行网关和子流程**。

**46. 离职后账号怎么失效？**
员工离职生效时停用账号；`JwtAuthFilter` 每次请求检查账号是否启用，状态缓存 60 秒，所以旧令牌最多 60 秒后失效。

**47. 权限怎么做的？**
两层：前端按角色裁剪菜单；后端每个 Controller 用 `@PreAuthorize` 限角色，写操作更严。通用查询还会按角色裁剪成本、毛利、工资列。

**48. 怎么防 SQL 注入？**
业务 SQL 全部参数化；通用只读查询的视图、过滤列、排序列走白名单，分页有上限；OA 条件表达式用自研解析器，不用脚本引擎。

**49. 职责分离怎么体现？**
审批人不能审批本人提交的单据；ECN 申请人不能会签；报销审批不能是本人；所有操作有 `@Audited` 审计日志。

### G. 数据、模拟与测试

**50. ★ 数据是真的吗？怎么来的？**
不是真的。`BusinessSimulator` 逐个工作日调度各子模拟，**每一笔都通过真实的业务服务生成**（不是直接插表），所以库存、成本、应收、应付、总账互相勾稽。客户、供应商都是虚构的。

**51. 怎么保证数据一致？**
两层：事务内生成凭证并校验借贷平衡；生成后做数据一致性检查（凭证全部平衡、总账对子账、增值税科目期末为 0、期间已结）。

**52. ★ 测试怎么做的？**
113 个单元测试，覆盖各计算类（成本、BOM 展开、APS、个税、SPC、免抵退、SLA 等）；数据层靠一致性检查；RAG 有 48 题评测集。**没有 Spring 集成测试和前端自动化测试**，这是我知道的缺口。

**53. 怎么验证业务规则对不对？**
规则用纯函数写，方便用已知答案测；跨模块的结果用不变量检查（比如 Σ库位库存 = 仓库现存量，总账 = 子账）。

**54. 举几个埋在数据里的业务故事。**
铜价上涨 20% 以上压低罩极和贯流毛利；客户 C003 回款恶化、超额度后新订单被冻结；2025-11 至 2026-01 伺服编码器虚焊，L5 良率下降、Cpk 跌破 1、客诉增多、现场故障率是平时 2–3 倍、质保金被迫补提；2025 年中 L8 冲床故障拖累 OEE；空压管网泄漏让非生产日电量约为平时 3 倍。

### H. AI 部分

**55. ★ RAG 技术助手的架构？**
LangGraph 搭了导入图和查询图。导入：MinerU 解析 PDF、视觉模型理解图片、父子两级切分、识别型号、BGE-M3 稠密 + 稀疏向量写入 Milvus（按 doc_key 幂等）。查询：改写与型号对齐 → 并行（混合检索、HyDE、联网搜索、ERP 实时数据）→ 加权 RRF → 重排 + 动态 TopK + 父文档扩展 → 带引用生成。

**56. 为什么用父子分块？**
子块小，检索定位准；父章节完整，喂给大模型的上下文不会被切碎。同一章节命中多个子块只保留一次。

**57. 为什么要混合检索 + RRF + 重排？**
稠密向量擅长语义，稀疏擅长关键词和型号编码；RRF 融合多路结果不需要对分数做归一化；重排用交叉编码器对候选做精排。我的消融实验里这几步在小评测集上差别不大（Hit@5 都是 0.972），**不要说它们大幅提升了效果**，要说清楚评测集只有 48 题。

**58. HyDE 是什么？**
先让模型生成一个假设性答案，用它去检索，弥补"用户问法"和"文档措辞"的差距。

**59. ★ 怎么防止 LLM 乱写 SQL？**
不让它写：ERP 数据走**参数化只读查询**，模型只决定"查哪个型号 / 哪个字段"，SQL 由代码生成；数据库账号是只读的。

**60. MCP 的安全是怎么考虑的？**
网关模式：沿用调用者本人的 JWT 和角色，不额外提权；写类工具只生成草稿或发起申请；**不开放任何审批工具**，审批必须人来做。

**61. 评估结果可信吗？**
有限可信：48 题是从数据库和手册自动生成的，完整链路答案准确率 0.958、检索 Hit@5 0.972；错的两题是型号歧义反问和变更原因召回。它说明链路能跑通，不代表真实用户问题上的表现。

**62. 经营分析 Agent 打算怎么做？**
指标口径库（YAML）→ LLM 生成查询 DSL → 编译成 SQL → 毛利归因（量、价、成本、结构），数据源是 `v_sales_fact` 等视图，用埋的业务故事做归因评测。目前还是计划，没有完成。

### I. 局限、改进与反思

**63. ★ 最大的局限是什么？**
三个：①没有集成测试和并发测试，高并发下的正确性没验证；②成本只有移动平均，没有标准成本差异分析；③MRP 和 APS 没合并。我会优先补集成测试。

**64. 如果重做，你会改什么？**
先写集成测试和接口契约；把 MRP 和 APS 合并成一次计算；加可观测性（Prometheus + Grafana，对账差异、SLA 违约、结账失败告警）；技术助手容器化。

**65. 如何支撑高并发？**
目前没做。思路：热点（库存、凭证号）用乐观锁或数据库行锁；报表走读库或汇总表；月结、MRP、APS 异步化；再考虑按业务域拆服务。

**66. 做的过程中遇到的最大的坑？**
挑一个真的：**存货总账和子账差万分之 0.2**。根因是移动平均单价舍入。我没有强行抹平，而是在对账页面把差异展示出来，并在文档里解释来源。——说明我更愿意暴露差异，而不是掩盖它。

**67. 你从这个项目学到了什么？**
把"规则写成纯函数 + 用不变量验收"这套方法用到了业务系统；也理解了业务数据不一致大多是因为"两个地方记了同一件事"。*（可以补一句你在科朗的 AI 项目如何和它互补。）*

**68. 这个项目和你的 AI 工程求职有什么关系？**
两方面：一是它提供了真实结构的企业数据，我能在上面做 RAG、Text2SQL 和分析 Agent；二是我在科朗做的 RAG 和知识图谱，需要理解产品、BOM、质量和 ERP 数据，这个项目帮我把业务搞懂了。

## 9. 局限与诚实边界（被追问时怎么答）

| 局限 | 事实 | 怎么回答 |
