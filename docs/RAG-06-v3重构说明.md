# 企业知识库 v3 重构说明

> 2026-10-15。按修改后的项目说明（项目一「企业知识库问答 Agent（多模态 RAG）」）重构 `assistant/app/kbase/`。
> 项目说明每一条对应到哪段代码，见 [RAG-07-模块与代码对照.md](RAG-07-模块与代码对照.md)；评测和调参结果见 [RAG-02-评测结果.md](RAG-02-评测结果.md) 第 11 节。

## 1. 改了什么（和 v2 对比）

| 方面 | v2 | v3 |
|---|---|---|
| 增量更新 | 文件级哈希；新版本整份重新切片、重新向量化 | 文件级 + chunk 级两层 SHA-256；没变的 chunk 沿用原来的向量和主体识别结果，只更新元数据；消失的标记失效 |
| 清洗 | 页眉页脚、全半角、型号写法 | 再加脱敏（手机号、身份证、银行卡、邮箱、敏感词）和术语单位统一 |
| 主体识别 | 正则找型号 | 新增 chunk 逐块调用大模型识别型号 / 系列，并校验原文证据；不过就退回规则 |
| 版本切换 | 版本指针一步切换；新旧版本的 chunk 各存一份 | chunk 有状态（PENDING / VALID / INVALID）和生效区间（valid_from / valid_to），一个事务里切状态和版本指针；回滚就是切回去 |
| 中断处理 | 失败时保持旧版本 | 再加补偿任务，清理 MinIO 和 Milvus 里的残留 |
| 通知 | 发件箱 + 轮询发送 | 持久化事件（和切换同一个事务）→ RabbitMQ → 消费者 → SMTP |
| 召回 | BGE-M3 稠密 + 稀疏两路 | 改写问题稠密 + HyDE 稠密 + Milvus 内置中文 BM25 三路，各 Top10 → RRF |
| 截断 | 重排后断崖截断 | 同上，上限 3（单变量调参选出）；先做主题确认（锁定型号 / 系列，型号不全时反问） |
| 上下文 | 每章截 4000 字 | 按 32K token 预算装：历史有上限，证据按顺序装，装不下的截断或丢弃并记录 |
| 查询日志 | 回答记录在 MySQL | 再加 MongoDB 查询日志（问题、改写、HyDE、召回、精排、答案与引用、反馈），Bad Case 池从这里筛 |
| 链路 | 每个节点一个 span | 节点里的改写、三路召回、精排、生成再嵌套 span（@observe）；挂文档版本、提示词版本、token |
| 图片 | MinIO 匿名可读，Markdown 里写公开地址 | 私有存储；Markdown 里只写 kbimg:// 引用；按生效版本登记；展示时鉴权后现签临时链接 |
| 图纸 | 只读模型空间；按图层规则归类尺寸；表头在上的明细表 | 模型空间 + 图纸空间、块展开、几何块文字、\S 堆叠公差、测量值 + 标注样式兜底、炸开的标注、GB 明细栏、续行合并、结构化卡片、缺项渲染复核 |
| 身份和权限 | MiniERP 账号的角色 | 公司 SSO（OIDC）：部门路径 + 职位 + 职级 → 角色 + 密级；部门沿组织树继承；未标注默认拒绝；向量、SQL、图片统一鉴权；后端通道注销 + 每日目录对账；只在内网和 VPN 网段提供服务 |
| ERP 数据 | 直接查本地镜像 | 工号映射金蝶用户，没有映射不返回，每次查询写审计 |
| 部署 | 本机进程 | 再加 Dockerfile、部署编排、Nginx（HTTPS、内网 / VPN 白名单、SSE、限流） |

## 2. 入库

```
上传 → 文件 SHA-256 判重 → 路由解析 ─┬─ 文档：pypdf / Docling / MinerU；扫描页、图片文件 → Qwen-VL
                                      ├─ 表格：选型表 → 型号–参数–数值–单位
                                      └─ 图纸：DWG → ODA → DXF → cad.py → 结构化卡片
     → 清洗、脱敏、术语单位统一 → 按章节切分 → 每块算归一化 SHA-256
     → 和当前生效的 chunk 比对：沿用 / 新增 / 消失
     → 新增的逐块主体识别（模型 + 证据校验）→ 质量门禁 → 新增的算向量
     → 暂存（新增写成 PENDING，检索看不到）→ 对账 → 事务切换 + 通知事件 → Markdown 和识别结果存 MinIO
```

**chunk 怎么认「没变」**：哈希前去掉开头的「【文档标题】」、页码标记、单独成行的页码、所有空白；章节标题保留（章节换了算内容变化）。
同样的内容在一份文档里出现两次时一对一复用，多出来的算新增。

**一行 chunk 怎么跨版本**：`kb_chunk.metas` 记「这个版本下的序号、章节、页码、父章节」，例如 `{"1": {...}, "2": {...}}`。
切换到哪个版本，就把那个版本的元数据写到当前列上；回滚同理。清理旧版本时只去掉那个版本的元数据，没有任何版本再用到、而且已失效的 chunk 才真正删除。

## 3. 一致性

| 环节 | 做法 |
|---|---|
| 幂等 | doc_id + version：同版本同内容跳过；版本号没升内容变了拒绝；比当前还旧拒绝；上次没导完的接着做（新增 chunk 主键确定，重写不重复） |
| 暂存 | 新增 chunk 写成 PENDING；检索在 Milvus 里只取 VALID，结果再按 SQL 状态过滤一遍 |
| 对账 | 这个版本应有的 chunk 在 Milvus 里都在、没有 SQL 里不存在的、状态一致、抽样内容哈希一致；能修的自动修 |
| 切换 | 一个 SQL 事务：PENDING → VALID、消失的 → INVALID（valid_to = 新版本）、沿用的换上新元数据、版本指针、通知事件 |
| Milvus 同步 | 提交后只改标量字段（partial upsert，同一批字段集合必须一致）；失败登记补偿任务 |
| 补偿 | 导入最终失败 → 登记 CLEAN_STAGED：删 PENDING chunk、Milvus 向量、MinIO 原文件和独有图片；按 30 秒 / 2 分钟 / 10 分钟 / 30 分钟退避，耗尽发告警事件 |
| 每日 | 全库对账、登记孤儿暂存数据的清理任务、清理过期旧版本 |

## 4. 问答

```
输入审核 → 理解（规则路由；追问才调模型改写）→ 主题确认 ─┬─ 参数：SQL
                                                        └─ 说明：改写 + HyDE → 三路召回 → RRF → 精排 → 断崖截断（≤3）
→ 兜底判断（为空 / 相关度低 / 无权限）→ 32K 预算装上下文 → 带出处生成 → 引用校验（不过重答，再不过摘录原文）→ 输出审核 → SSE
```

- **主题确认**：问题里的型号和型号库比对。写全了就锁定；写了前半截（KL-SV-80）只有一个候选就补全，有多个候选时参数类问题反问（数值不能猜），说明类问题把候选都当过滤条件；追问沿用会话里锁定的主题。锁定结果按 `item_name` 或 `series` 过滤检索，过滤后太少就放开再召回一次。
- **HyDE**：一次调用同时出改写和假设答案；首轮问题按（问题、提示词版本、锁定主题）缓存一天。失败就跳过这一路，记为降级。
- **上下文预算**：默认 32000，给回答留 2048；历史最多 3000（先丢最早的轮次，摘要保留）；证据按顺序装，最后一条装不下就截到段落边界，再装不下就丢掉；明细记进链路和回答日志。

## 5. 身份和权限

- **登录**：`/auth/sso/login` 生成 state、nonce、PKCE 存 Redis → 公司 SSO → `/auth/sso/callback` 用授权码换 ID Token（RS256 验签，核对 iss、aud、exp、nonce）→ 解析身份 → 签发知识库自己的登录凭证（独立密钥、受众 kbase，8 小时，拿去调 ERP 无效）→ 回到前端 `/kbase#token=…`（放在 # 后面，不进服务器日志）。
- **身份 → 权限**：`resources/sso_rules.json`。部门决定基本角色，职位补充角色，职级决定密级（M 级、P6 以上到机密，P1–P5 到内部），销售、生产、采购、财务封顶内部。部门路径每一级都变成一个 `D:部门编号` 标记。
- **文档标注**：`acl_groups` 写 `ALL`、角色名或 `D:部门编号`，密级必填；没标注的入库时就拒收，检索时也挡掉（Milvus 用 level = -1、SQL 用 sec_level IS NULL）。
- **吊销**：SSO 后端通道注销（离职、禁用、强制下线）→ 记吊销时间（毫秒），签发早于它的凭证全部作废；每天和公司目录（SCIM）全量对账兜底。
- **身份异常**：目录不可用沿用最后一次成功解析的身份（最多 7 天，提示用户并记审计），没有就要求重新登录；离职、禁用、查无此人拒绝；没匹配到规则只给公开资料并告警。
- **网络**：Nginx 只监听内网地址、按办公网和 VPN 地址池放行；应用里再校验一次来源地址，只采信受信任代理写的 X-Forwarded-For。远程办公用公司电脑连 VPN 后访问，没有公网入口。

## 7. 部署（Docker + Nginx）

| 文件 | 作用 |
|---|---|
| `assistant/Dockerfile` | 服务镜像（问数、知识库、跟单共用，APP_MODULE 选启动哪个）。依赖按 uv.lock 装，torch / torchvision 换成 CPU 版：镜像从 21.6GB 降到 3.8GB。非 root 用户运行，带健康检查 |
| `assistant/deploy/kbase/docker-compose.yml` | 知识库服务 + 入口网关；中间件沿用 `assistant/docker-compose.yml` 的网络；宿主机端口只绑内网地址 |
| `assistant/deploy/nginx/kbase.conf` | HTTPS（公司内部 CA）、SSE 不缓冲、按来源限流、运维接口只给运维网段、安全响应头；X-Forwarded-For 用网关看到的地址覆盖 |
| `assistant/deploy/nginx/allowlist.conf` | 来源白名单：办公网、车间网、VPN 地址池、运维网段（示例网段，按公司实际修改），其余 403 |

验证过的：镜像构建成功，容器里能导入服务和全部依赖；Nginx 配置 `nginx -t` 通过；用生产白名单时本机访问返回 403，在请求头里伪造 VPN 地址也是 403；换成包含本机网段的测试白名单后经网关能访问到知识库服务。
没验证的：整套编排在服务器上起起来（本机内存 16G，再加载一份模型会把内存撑爆）。

## 10. 发现并修掉的问题

- `docker-compose.yml` 的 minio-init 原来会给 images/ 开匿名读，每次重启都把私有桶改回公开：改成 `set none`，服务启动时也强制私有。
- 知识库签发的 SSO 凭证原来和 MiniERP 用同一个密钥，ERP 后端也认：改成独立密钥和受众，现在拿去调 ERP 返回 401。
- 镜像里的 torch 默认是带 CUDA 的版本（21.6GB），换成 CPU 版；torchvision 也要一起换，不然导入时报 `torchvision::nms does not exist`。
- RAGAS 多线程并发导入 langsmith 时偶发半初始化（`_context` 没有 `_ADDRESS`），改成先在主线程导入。
- Milvus partial upsert 同一批里字段集合不同会整批失败（生效和失效的 chunk 混在一起发）：按字段集合分组发。
- 吊销时间和签发时间按整秒比较，同一秒内的旧凭证不失效：改成毫秒。

## 11. 还没做 / 限制

- Qwen3-32B、Qwen-VL 没有在 vLLM 上实测；演示用 DeepSeek，视觉模型当前没有可用的 key。
- SSO 和公司目录只连过模拟端；接真实环境要配置 `SSO_*` 并确认对方 ID Token 里部门路径、职级的字段名（不一致时改 `auth/directory.py` 的 `to_claims` 和 `auth/sso_mock.py` 对应的声明）。
- 镜像在 Mac（arm64）上构建，生产环境要在 x86 服务器上重新构建；GPU 推理不在这个镜像里（走 vLLM 服务）。
