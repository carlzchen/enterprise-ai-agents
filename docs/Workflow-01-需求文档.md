# 销售与采购跟单自动化 Workflow：需求文档（User Story 与 Use Case）

> 版本：2026-10-12（需求阶段，尚未开发）
> 来源：《销售与采购跟单自动化 Workflow 设计》（2026-10-07）
> 对象：产品、开发、测试、业务方评审
> 背景企业：科朗这类微特电机制造企业（罩极、贯流、无刷、步进、伺服、减速电机）
> 依赖的已有项目：企业知识库问答（项目一，负责参数理解和选型匹配）、经营与人力问数 Copilot（项目二，负责查历史价格、订单、回款）

**读这份文档前要知道的三点**

1. 文中的流程是按一般电机制造企业写的假设，**还没有做业务调研**。第 9 节列出了开工前必须问清楚的问题，答案会改变优先级和部分验收标准。
2. 所有带数值的目标（响应时间、准确率、提醒天数、毛利阈值）都**没有定**，文中用「待定」或「可配置」标出，要在调研测出基线后和业务方一起定。
3. 原设计稿里的通知和审批入口写的是企业微信或钉钉。科朗用的是飞书、ERP 是金蝶 EAS，本文按这两项写；审批用哪个 OA 仍待调研确认。

## 1. 为什么要做

| 现在的问题 | 具体表现 | 做完以后 |
|---|---|---|
| 信息锁在邮件里 | 客户需求、规格书、图纸、还价、样品反馈、PO 都在邮件和附件里，进度只有经手人知道 | 每封业务邮件都归到某个客户、某个商机、某一步，有负责人 |
| 重复劳动多 | 读规格书找型号、翻历史价格、在 Excel 里算报价、把 PO 手工录进 ERP | 系统读懂并起草，人只做确认和决策 |
| 容易漏 | 报价有效期、样品反馈、交期变更没人提醒，客户催了才发现 | 每个商机都有下一步和到期提醒 |
| 交接难 | 业务员休假或离职，客户历史和在途事项很难交接 | 按客户和商机能看到完整的来往记录和当前状态 |

**一句话目标**：把散落在邮件里的询价、报价、议价、样品、订单跟单，变成可追踪、可半自动推进的流程。AI 负责读懂和起草，人负责确认和决策。

**目标指标**（基线都要先测）

| 指标 | 现状 | 方向 |
|---|---|---|
| 询价首次响应时间 | 待测 | 明显缩短，标准品当天回复 |
| 标准品报价周期（询价到报价发出） | 待测 | 明显缩短 |
| PO 录单方式 | 手工录入 | 自动抽取加人工核对 |
| 跟进遗漏数 | 无统计 | 每个商机都有下一步和到期提醒 |
| 起草内容的采纳率（直接采用或小改后采用） | 无 | 作为「好不好用」的主要判断依据 |

## 2. 用户角色

| 角色 | 负责什么 | 最关心什么 |
|---|---|---|
| 销售（业务员） | 客户关系、报价、议价、拜访 | 快速回复客户，不漏跟进，谈价时心里有底 |
| 销售助理 | 邮件初筛、资料整理、录单 | 邮件别分错，修正要方便 |
| 跟单员 | 订单交付进度、回复客户催货、出货资料 | 提前知道哪张单有风险，少查系统 |
| 销售经理、销售总监、总经理 | 报价和让价审批 | 审批时能看到成本、毛利、历史成交价和理由 |
| 应用工程师（技术支持） | 选型、改型可行性评估 | 一眼看出客户要求和推荐型号差在哪 |
| 研发工程师 | 打样、改样、新开发评估 | 打样任务和客户反馈的问题清楚、不丢 |
| 计划员 | 排产、可承诺交期 | 交期评审和缺料影响 |
| 采购员 | 询比价、下单、交期跟催、对账 | 比价表自动出，延期早知道 |
| 来料检验员（IQC） | 来料检验 | 检验结果能带到对账环节 |
| 财务 | 信用额度、付款条件、回款、三单匹配 | 超信用和条款变化有人拦，差异自动列出 |
| 仓库 | 样品和成品出库、发货 | 出库指令和快递单号回填 |
| 系统管理员 / AI 开发 | 规则维护、权限、评测、运维 | 规则可配置，全程留痕，改动能回归 |

## 3. 范围

**要做的**

- 销售线八个流程：W1 邮件分拣、W2 询价理解与选型、W3 报价、W4 议价与竞标、W5 客户拜访、W6 样品管理、W7 订单与合同评审、W8 交付跟单与回款
- 采购线五个流程：P1 询比价、P2 原材料价格联动、P3 交期跟催、P4 到货检验对账付款、P5 新供应商准入和新物料承认
- 流程之间的衔接：用「商机」贯穿销售线，流程之间通过事件交接
- 人工确认入口：飞书卡片加一个 Web 待办中心
- 评测集和业务指标统计

**不做的**

- 不让大模型计算或决定任何数字：价格、毛利、底价、信用额度、可承诺交期都由代码按规则和业务系统数据计算
- 不自动登录客户的采购平台，不自动提交投标
- 初期不自动外发任何邮件、报价单、订单确认书
- 第一阶段不向 CRM 和 ERP 写数据
- 客诉处理流程（如 8D）：本期只识别并分派，不做流程
- 不用 RPA 模拟点击去操作没有接口的系统
- 客户数据和图纸不出内网，不调用外部模型服务

## 4. 总体业务规则

下面八条对所有流程都适用，后面的验收标准不再逐条重复。

| 编号 | 规则 | 含义 |
|---|---|---|
| R1 | 数字不让大模型算 | 报价、毛利、底价、信用额度、交期由代码计算；大模型只负责把参数读出来、把邮件写出来 |
| R2 | 对外发出的东西必须人工确认 | 发给客户和供应商的邮件、报价单、订单确认书，初期一律由人点「确认发送」；稳定后对低风险动作逐个放开 |
| R3 | 长流程持久化 | 样品、报价跟进这类持续几周的流程，服务重启、代码发版后能从断点继续 |
| R4 | 按置信度分流 | 抽取或分类置信度高的自动流转，低的进人工待办；人工修正的结果回流进评测集 |
| R5 | 幂等和去重 | 同一封邮件重复拉取、同一张 PO 重复发来，不能重复建单；用邮件 Message-ID、PO 号、报价单号做唯一键 |
| R6 | 复用已有权限体系 | 销售只看自己负责的客户；成本、毛利、底价按角色可见（沿用问数项目的角色权限） |
| R7 | 数据不出内网 | 使用内网私有部署的模型 |
| R8 | 先做助手，再做自动化 | 第一阶段只读、只起草、不写业务系统；准确率和业务信任建立后再逐步放开写入 |

## 5. User Story

格式：**作为**某角色，**我想**做某事，**以便**达到某目的。
优先级：P0 = 所在阶段必须有；P1 = 所在阶段应该有；P2 = 可以后做。
所有故事的状态都是「未开始」，表里不再单列。

| 编号 | 用户故事 | 验收标准 | 优先级 |
|---|---|---|---|

| US-106 | 作为**销售**，我想让邮件自动关联到已有的商机或订单，以便不用自己去找上下文。 | ① 优先用报价单号、PO 号精确匹配；② 匹配不到再按型号和线程匹配；③ 关联结果可以一键改正。 | P0 |
| US-107 | 作为**销售**，我想在飞书里收到分派通知，以便不用盯着邮箱。 | ① 通知里有客户、意图、要点、处理时限；② 可以直接点进待办；③ 分派后开始计时。 | P0 |
| US-108 | 作为**销售助理**，我想有一个「待确认」队列处理系统拿不准的邮件，以便错误不流到后面。 | ① 置信度低、陌生客户、关联不上单据的邮件进队列；② 一键修正意图、客户、关联对象；③ 修正结果自动加入评测集。 | P0 |
| US-109 | 作为**系统管理员**，我想保证同一封邮件被重复拉取时不会重复建记录，以便数据不乱。 | ① 以 Message-ID 为唯一键；② 重复到达时只更新不新建。 | P0 |
| US-110 | 作为**销售**，我想中英文混写的外贸邮件也能正确处理，以便出口业务同样能用。 | ① 评测集里包含中文、英文、中英混写三类；② 三类分别统计准确率。 | P1 |

|---|---|---|---|

| US-206 | 作为**应用工程师**，我想由我确认选型结论后才进入报价，以便技术判断有人负责。 | ① 工程师可以采纳、改选或驳回；② 结论和理由留痕；③ 确认后触发报价流程。 | P0 |
| US-207 | 作为**销售**，我想无匹配的需求自动转给研发评估，以便不卡在我手里。 | ① 生成研发评估任务；② 提示开发费和模具费需要单独核算、报价周期较长。 | P1 |

### E3 报价（W3）

| 编号 | 用户故事 | 验收标准 | 优先级 |
|---|---|---|---|
| US-301 | 作为**销售**，我想系统自动把成本拉出来，以便不用找财务和采购要数。 | ① 材料成本 = BOM × 最新物料单价；② 人工和制造费用取 ERP 标准成本或财务核定费率；③ 改型和新开发费用取技术评估结果；④ 包装、运输、关税按贸易条款的规则计算。 | P0 |
| US-302 | 作为**销售经理和财务**，我想自己维护定价规则，以便调整策略时不用找开发。 | ① 可按客户等级、产品线、年用量设置目标毛利率和最低毛利率；② 支持数量阶梯价；③ 规则修改后不改代码即生效；④ 规则变更留痕。 | P0 |
| US-303 | 作为**销售**，我想报价时看到历史成交价，以便报得有依据。 | ① 显示同一客户同型号的上次成交价；② 显示同类客户的成交价区间；③ 数据来自问数项目的查询能力。 | P0 |
| US-304 | 作为**销售**，我想系统直接生成报价草稿，以便不再在 Excel 里算。 | ① 所有价格由代码按规则计算；② 草稿里显示成本构成和毛利率（按角色可见）；③ 销售可以调整价格，调整后毛利率实时重算。 | P0 |
| US-305 | 作为**审批人**，我想低毛利的报价自动送到对应层级审批，以便把住价格。 | ① 不低于目标毛利率由销售经理批；介于最低和目标之间由销售总监批；低于最低毛利率由总经理批并必须填写理由；② 阈值可配置；③ 审批卡片显示成本构成、毛利率、历史成交价、报价理由。 | P0 |
| US-306 | 作为**销售**，我想审批通过后自动生成报价单 PDF 和邮件草稿，以便确认后直接发。 | ① 报价单包含：型号与规格、阶梯单价、币种、最小起订量、交期、贸易条款、付款条件、报价有效期、原材料联动条款、模具费或开发费（如有）；② 邮件由我确认后才发送；③ 发出后商机状态变为「已报价」。 | P0 |
| US-307 | 作为**销售**，我想在报价快到期而客户没回复时收到提醒和跟进邮件草稿，以便不让报价白白过期。 | ① 到期前 N 天提醒（N 可配置）；② 附跟进邮件草稿；③ 客户已回复则不提醒。 | P0 |
| US-308 | 作为**销售**，我想每一版报价都留痕，以便日后查得到当时报了什么、依据是什么。 | ① 每版报价保存价格、成本快照、规则版本、审批记录；② 报价单号唯一。 | P0 |

| 参与者 | 系统；销售助理（处理待确认）；销售、跟单员、采购员（接收分派） |
| 触发 | 业务邮箱收到新邮件 |
| 前置条件 | 系统有权读取业务邮箱；客户、供应商档案可查 |
| 对应故事 | US-101 至 US-110 |

**基本流程**

1. 系统拉取新邮件，按 Message-ID 判断是否已处理过。
2. 系统按 Message-ID、In-Reply-To 把邮件归到已有会话，没有则新建会话。
3. 系统按发件人邮箱域名匹配客户或供应商档案。
4. 系统去掉正文里引用的历史邮件，识别意图，得到意图列表。
5. 系统解析附件（PDF、Excel、图纸、图片）。
6. 系统按固定的数据结构抽取字段，缺失的标为空。
7. 系统按报价单号、PO 号、型号、线程把邮件关联到已有商机或订单。
8. 系统创建或更新记录，按意图分别派发到对应流程（见下表）。
9. 系统把任务分派给负责人，在飞书发通知，开始计响应时限。

**扩展流程**

- 1a. 邮件已处理过：只更新，不新建，结束。
- 3a. 域名匹配不上（陌生域名或个人邮箱）：标记为「潜在新客户」，进待确认队列。
- 3b. 邮件是转发的：从正文里识别真实发件人，再做匹配。
- 4a. 一封邮件有多个意图（例如「报价收到了，PO 附上，请确认交期」）：每个意图各派发一次。
- 4b. 分类置信度低：进待确认队列，由销售助理一键修正。
- 5a. 附件解析失败：标记该附件未解析，正文照常处理，提示人工查看附件。
- 7a. 关联不到已有单据：新询价则新建商机；其他意图进待确认队列。
- 7b. 关联错了：负责人在待办里一键改正，后续记录跟着迁移。
- 8a. 意图是「其他」：归档，不派发。
- 8b. 意图是质量投诉：只分派给对应负责人，不进入本期的任何流程。

**后置条件**：每封业务邮件都有意图、所属客户、关联对象和负责人；人工修正的结果已加入评测集。

**意图与派发**

| 意图 | 典型邮件 | 派发到 |
|---|---|---|
| 新询价 | 附规格要求或询价表，问有没有合适型号、多少钱 | UC-02 |
| 报价跟进或还价 | 嫌贵、给目标价、问能否降价 | UC-04 |
| 招标通知 | 客户采购平台发来的竞价或招标邀请 | UC-05 |
| 样品相关 | 申请样品、样品测试反馈、问样品寄到哪 | UC-07 |
| 采购订单 | 附 PO 文件 | UC-08 |
| 交期或物流询问 | 问货什么时候到、要求提前或推迟 | UC-09 |
| 质量投诉 | 不良反馈、要求 8D 报告 | 只分派，本期不做流程 |
| 供应商报价或交期回复 | 采购询价的回复、交期确认 | UC-10、UC-12 |
| 发票或对账 | 对账单、发票 | UC-13 或财务 |
| 其他 | 广告、通知、无关邮件 | 归档 |

### UC-02 询价理解与选型匹配（W2）

| 项目 | 内容 |
|---|---|
| 参与者 | 系统、销售、应用工程师、研发工程师 |
| 触发 | UC-01 派发了一条新询价；或拜访纪要里确认了新需求 |
| 前置条件 | 标准品参数库可查；各产品线的必填参数清单已由技术部门确认 |
| 对应故事 | US-201 至 US-207 |

**基本流程**

1. 系统把客户的参数标准化：换算单位，统一同义词。
2. 系统按产品线检查必填参数是否齐全。
3. 系统把参数转成筛选条件，在标准品参数库里筛出候选型号。
4. 系统查找历史上相似的询价和当时的方案。
5. 系统用代码逐项比较客户要求和候选型号的数值，生成差异表和匹配分级。
6. 应用工程师查看差异表，确认选型结论。
7. 系统发出「需求已确认」事件，进入 UC-03。

**扩展流程**

- 2a. 缺少必填参数：系统列出缺失项并起草澄清邮件，销售确认后发出，商机状态变为「需求确认中」；客户回复后（经 UC-01）回到第 1 步。
- 5a. 近似匹配：差异表列出需要改动的项（如轴长、出线长度、端子），应用工程师确认可行性和改型费用。
- 5b. 无匹配：转研发评估，开发费和模具费单独核算，告知销售报价周期较长。
- 6a. 工程师不采纳推荐：改选其他型号或驳回，记录理由，计入采纳率统计。

**后置条件**：商机上有标准化的需求、选型结论和差异表。

**业务规则**：「是否满足」只由代码比较数值，大模型不判断大小。

**必填参数清单（示例，需与技术部门逐条确认）**

| 产品线 | 必填参数 | 客户常漏掉的 |
|---|---|---|
| 步进电机 | 机座号、步距角、保持力矩、相电流、机身长度 | 轴伸长度与形状、出线方式、驱动器型号 |
| 交流罩极电机 | 额定电压与频率、输出功率、转速、转向 | 温升要求、噪音要求、安全认证 |
| 无刷直流电机 | 额定电压、额定转速、额定力矩、尺寸 | 是否带驱动、控制方式、寿命要求 |
| 所有产品线 | 年用量、目标交期 | 目标价、包装方式、贸易条款 |

### UC-03 报价（W3）

| 项目 | 内容 |
|---|---|
| 参与者 | 系统、销售、销售经理、销售总监、总经理、财务（维护规则） |
| 触发 | 「需求已确认」事件；或「样品已承认」事件（出量产报价） |
| 前置条件 | 选型已确认；BOM 和物料单价可查；定价规则已配置 |
| 对应故事 | US-301 至 US-308 |

**基本流程**

1. 系统拉取成本：材料、人工与制造费用、改型或开发费用、包装运输关税。
2. 系统按定价规则计算各数量阶梯的价格和毛利率。
3. 系统查出同一客户同型号的上次成交价和同类客户的成交价区间。
4. 系统生成报价草稿，销售查看并可调整。
5. 系统按毛利水平把报价送到对应审批人。
6. 审批通过后，系统生成报价单 PDF 和邮件草稿。
7. 销售确认后发送，商机状态变为「已报价」，系统发出「报价已发出」事件并启动有效期计时。

**扩展流程**

- 1a. 成本数据缺失（如新物料没有单价）：停在本步，提示需要采购或技术补充估价。
- 4a. 销售调整了价格：毛利率由代码重算，审批层级随之变化。
- 5a. 毛利低于最低毛利率：送总经理审批，销售必须填写理由。
- 5b. 审批被驳回：退回销售修改，重新走第 4 步。
- 7a. 有效期到期前 N 天客户没有回复：给销售发提醒和跟进邮件草稿。
- 7b. 原材料价格波动超过阈值（来自 UC-11）：把这份在途报价标记为「受影响」，提醒销售是否需要更新。

**后置条件**：报价单有唯一编号，价格、成本快照、规则版本、审批记录都已保存。

**审批规则（阈值由公司定）**

| 报价毛利率 | 审批人 |
|---|---|
| 不低于目标毛利率 | 销售经理 |
| 介于最低毛利率和目标毛利率之间 | 销售总监 |
| 低于最低毛利率（战略性报价） | 总经理，必须填写理由 |

### UC-04 议价（W4）

| 项目 | 内容 |
|---|---|
| 参与者 | 系统、销售、审批人 |
| 触发 | UC-01 识别出还价邮件 |
| 前置条件 | 该商机有已发出的报价 |
| 对应故事 | US-401 至 US-405 |

**基本流程**

1. 系统从邮件里抽取目标价、还价轮次、客户给的理由。
2. 系统计算：当前报价与目标价的差距、底价、该客户历史让价幅度、量价关系。
3. 系统按规则生成候选策略，大模型把它们写成可读的建议。
4. 销售选择一种策略并确定新价格或新条件。
5. 系统起草回复邮件，销售确认后发送。
6. 系统记录本轮结果。

**扩展流程**

- 1a. 邮件里没有明确的目标价：标为空，提示销售向客户确认。
- 4a. 新价格超出销售权限：按 UC-03 的审批规则走审批，通过后继续第 5 步。
- 4b. 选择「以方案换价格」（换材料或改用标准品）：先请技术确认可行，再继续。
- 4c. 目标价低于底价且不具战略价值：选择放弃，商机标记为输单并记录原因。
- 6a. 客户接受：等待 PO（进入 UC-08）或样品（进入 UC-07）。

**后置条件**：每一轮的目标价、我方报价、策略、结果都有记录。

**候选策略**

| 策略 | 适用情况 |
|---|---|
| 接受 | 目标价高于底价，且在销售权限内 |
| 部分让价 | 报一个介于两者之间的价格，附让价理由 |
| 以条件换价格 | 提高起订量、延长交期、调整付款条件、改用标准包装 |
| 以方案换价格 | 推荐降本方案，需技术确认 |
| 放弃 | 目标价低于底价，且不具战略价值 |

### UC-05 竞标准备（W4）

| 项目 | 内容 |
|---|---|
| 参与者 | 系统、销售、销售助理 |
| 触发 | UC-01 识别出招标通知 |
| 前置条件 | 资质文件库可用 |
| 对应故事 | US-406 至 US-409 |

**基本流程**

1. 系统解析标书：技术参数、资质要求、报价格式、截止时间。
2. 系统按要求列出资质文件清单，从文件库取最新有效版本。
3. 技术参数走 UC-02 选型，价格走 UC-03 报价和审批。
4. 系统按标书格式预填报价表。
5. 截止前系统分级提醒。
6. 销售登录客户平台，核对后人工提交。
7. 结果出来后，销售记录赢单或输单及原因。

**扩展流程**

- 2a. 某份证书已过期或快过期：提示销售助理更新，清单上标红。
- 2b. 文件库里没有标书要求的某项资质：列为缺项，提示销售判断是否还参与。
- 5a. 截止前仍未完成审批：升级提醒销售经理。

**后置条件**：投标材料齐备，提交动作和结果有记录。

**业务规则**：系统不自动登录客户平台，不自动提交。

### UC-06 客户拜访准备与纪要（W5）

| 项目 | 内容 |
|---|---|
| 参与者 | 系统、销售 |
| 触发 | 日历或 CRM 里有拜访计划，系统在前一天触发；拜访结束后销售口述 |
| 前置条件 | 能读取拜访计划；问数项目的查询能力可用 |
| 对应故事 | US-501 至 US-504 |

**基本流程**

1. 拜访前一天，系统生成客户简报并推送给销售。
2. 拜访后，销售用语音或文字口述要点。
3. 系统整理成结构化纪要：参会人、客户需求、竞品信息、我方承诺、下一步。
4. 销售确认或修改纪要。
5. 系统把纪要写入 CRM，把承诺事项生成待办和到期提醒。

**扩展流程**

- 1a. 客户是新客户，没有交易记录：简报只包含概况和在途事项，并注明没有历史交易。
- 3a. 承诺里的时间是模糊的（「下周」「月底前」）：系统换算成具体日期并请销售确认，不直接写入。
- 3b. 纪要里出现新需求：提示销售是否创建询价，确认后进入 UC-02。
- 5a. 第一阶段不写 CRM：纪要和待办只保存在本系统。

**后置条件**：纪要已保存，每条承诺都有负责人和到期日。

### UC-07 样品管理（W6）

| 项目 | 内容 |
|---|---|
| 参与者 | 系统、销售、审批人、仓库、研发工程师、客户（通过邮件） |
| 触发 | UC-01 识别出样品申请邮件；或销售手动发起 |
| 前置条件 | 库存可查；样品收费规则已配置 |
| 对应故事 | US-601 至 US-610 |

**基本流程**

1. 销售发起样品申请，系统按规则判断免费还是收费，走审批。
2. 系统查库存，有标准品库存则生成仓库出库指令。
3. 样品完成内部测试，生成测试报告。
4. 仓库寄样，快递单号回填，系统跟踪物流。
5. 客户签收，系统通知客户。
6. 签收后第 7 天、第 14 天，系统提醒销售跟进反馈。
7. 客户反馈邮件经 UC-01 进入，系统抽取结论和具体问题。
8. 结论为通过：签署样品承认书或规格书，系统锁定承认的规格版本，发出「样品已承认」事件。

**扩展流程**

- 1a. 审批不通过：流程结束，通知销售。
- 2a. 没有库存或需要改型：给研发或生产创建打样任务，带预计完成日期；完成后进入第 3 步。
- 2b. 打样超过预计完成日期：提醒研发和销售。
- 3a. 内部测试不合格：退回研发，不进入寄样。
- 6a. 两次提醒后仍无反馈：升级提醒销售经理，是否继续跟进由销售决定。
- 7a. 结论为不通过：生成问题单给研发，改样后回到第 3 步，轮数加一。
- 7b. 结论为有条件通过：列出条件，由销售和技术决定是改样还是带条件承认。
- 8a. 样品承认后：出量产报价（UC-03）或等待 PO（UC-08）。
- 任意步骤：服务重启或发版后，流程从当前步骤继续，计时不丢。

**后置条件**：样品单有完整的轮次记录；通过的样品有锁定的规格版本。

**业务规则**：这是会「等」很久的流程（等打样、等快递、等客户测试），必须用带持久化状态和定时器的工作流引擎实现。

### UC-08 订单与合同评审（W7）

| 项目 | 内容 |
|---|---|
| 参与者 | 系统、销售助理、销售、应用工程师、计划员、财务 |
| 触发 | 「PO 已收到」事件（UC-01 识别出带 PO 附件的邮件） |
| 前置条件 | 该客户有档案；报价记录、样品承认版本、ERP 数据可查 |
| 对应故事 | US-701 至 US-710 |

**基本流程**

1. 系统从 PO 附件抽取：PO 号、型号、数量、单价、币种、交期、收货地址、付款条件、贸易条款。
2. 系统检查 PO 号是否已经建过单。
3. 系统逐项自动核对（见下表），差异标红。
4. 系统按差异类型把会签任务分给销售、计划、财务、技术。
5. 各方处理完差异，评审通过。
6. 系统在 ERP 创建销售订单，发出「销售订单已创建」事件。
7. 系统起草订单确认书，销售确认后发送。

**扩展流程**

- 1a. 单价或数量的抽取置信度低：标出，由销售助理对照原件核对。
- 2a. PO 号已存在：直接拦截并提示，流程结束。
- 3a. 没有任何差异：走简化评审，直接到第 6 步。
- 3b. 找不到对应的有效报价：提示销售确认价格来源。
- 5a. 某项差异需要和客户沟通（如交期做不到）：系统起草沟通邮件，销售确认后发送；客户回复后继续评审。
- 5b. 评审不通过：不建单，通知销售并记录原因。
- 6a. ERP 没有开放写接口，或处于第一阶段：生成待导入数据，由销售助理在 ERP 里一键导入。

**后置条件**：ERP 里有且只有一张对应的销售订单；评审过程和差异处理有记录。

**自动核对项**

| 核对项 | 对照来源 | 发现问题时 |
|---|---|---|
| 单价 | 该客户该型号的有效报价（含阶梯价、是否过期） | 提示销售确认 |
| 型号与版本 | 样品流程里承认的规格版本 | 提示技术确认 |
| 交期 | ERP 的可承诺量、产能、物料齐套情况 | 提示计划给出可行日期 |
| 付款条件 | 客户档案里的约定条款 | 提示财务确认 |
| 信用额度 | 信用额度 − 已用额度 − 未回款 | 超额时转财务审批 |
| 重复下单 | 已有的 PO 号 | 直接拦截 |

### UC-09 交付跟单与回款（W8）

| 项目 | 内容 |
|---|---|
| 参与者 | 系统、跟单员、销售、计划员、采购员、财务 |
| 触发 | 「销售订单已创建」事件；每日定时检查；客户的交期或物流询问邮件 |
| 前置条件 | ERP 里的订单、工单、库存、物流信息可查 |
| 对应故事 | US-801 至 US-808 |

**基本流程（主动监控）**

1. 系统每天检查所有在途销售订单的工单进度和物料齐套情况。
2. 订单按期完工：触发出货准备，生成装箱单和发票。
3. 出货后物流单号回填，系统跟踪物流。
4. 客户签收后触发开票，系统按账期计算到期日。
5. 到期前系统提醒销售。
6. 回款到账，商机关闭。

**扩展流程**

- 1a. 发现缺料：系统反查是哪张采购单延期，发出「缺料」事件，触发 UC-12。
- 1b. 预计无法按期交付：提前通知销售，起草交期变更说明，销售确认后发送。
- 2a. 出口订单：另外生成报关资料。
- 5a. 逾期未回款：分级升级（销售、销售经理、财务介入），发出「回款逾期」事件，逾期金额计入该客户的信用占用。

**分支流程 A：客户问「货到哪了」**

1. UC-01 把邮件分类为交期或物流询问。
2. 系统按 PO 号查 ERP 订单状态和物流信息。
3. 系统起草回复：已发货的附单号，未发货的给出预计日期。
4. 跟单员确认后发送。
- 2a. 邮件里没有 PO 号、也关联不到订单：进待确认队列，由跟单员指定订单。

**分支流程 B：客户要求提前或推迟交货**

1. 系统整理客户的要求，评估产能和物料。
2. 计划员确认是否可行并给出日期。
3. 修改 ERP 订单，系统起草回复，跟单员确认后发送。
- 2a. 涉及加急费用或违约：走审批后再回复。
- 2b. 做不到：起草说明并给出可行日期。

**后置条件**：每张订单的交付和回款状态可查；风险订单有负责人和处理记录。

**业务规则**：对客户的回复必须基于确定的查询结果，不允许大模型自己描述订单状态。

### UC-10 采购询比价（P1）

| 项目 | 内容 |
|---|---|
| 参与者 | 系统、采购员、审批人、供应商（通过邮件） |
| 触发 | ERP 的物料需求计算生成请购；或研发打样需要新物料 |
| 前置条件 | 合格供应商名录和价格协议可查 |
| 对应故事 | US-901 至 US-903 |

**基本流程**

1. 系统检查该物料是否有有效的价格协议。
2. 没有协议价：系统从合格供应商名录选出候选，起草询价邮件。
3. 采购员确认后群发。
4. 供应商回复经 UC-01 进入，系统抽取单价、起订量、交期、付款条件、报价有效期。
5. 系统生成比价表，附各供应商的历史交付准时率和来料合格率。
6. 采购员选定供应商，按金额走审批。
7. 系统生成采购订单。

**扩展流程**

- 1a. 有有效的价格协议：直接按协议价生成采购订单草稿，跳到第 6 步。
- 4a. 到期仍有供应商未回复：提醒采购员，可以催问或按已有回复比价。
- 4b. 回复里缺关键信息：标为空，提示采购员补问。
- 6a. 选定的不是最低价：采购员需填写理由。
- 6b. 需要新供应商：进入 UC-14。

**后置条件**：采购订单已生成；比价过程和选择理由有记录。

### UC-11 原材料价格联动（P2）

| 项目 | 内容 |
|---|---|
| 参与者 | 系统、销售、采购员 |
| 触发 | 每日定时 |
| 前置条件 | 能取得铜、钢等大宗原材料的价格指数；报价时记录了基准价 |
| 对应故事 | US-904 |

**基本流程**

1. 系统读取当天的原材料价格指数。
2. 系统与各在途报价、订单的基准价比较。
3. 波动超过阈值：系统更新受影响物料的估算成本。
4. 系统找出受影响的在途销售报价和订单，发出「原材料价格超阈值」事件。
5. 系统提醒销售：报价是否需要更新、是否触发合同里的调价条款。
6. 系统提醒采购：是否需要锁价或提前备料。

**扩展流程**

- 1a. 当天取不到价格指数：沿用上一次的值并告警，不触发联动。
- 2a. 波动未超过阈值：不处理。
- 5a. 销售决定更新报价：回到 UC-03 重新核算和审批。

**后置条件**：受影响的报价和订单都被标记，销售和采购各自收到提醒。

### UC-12 采购交期跟催（P3）

| 项目 | 内容 |
|---|---|
| 参与者 | 系统、采购员、计划员、销售、供应商（通过邮件） |
| 触发 | 采购订单承诺交期前 3 天（可配置）；或收到「缺料」事件 |
| 前置条件 | 采购订单和承诺交期可查 |
| 对应故事 | US-905、US-906 |

**基本流程**

1. 系统起草交期确认邮件。
2. 采购员确认后发送。
3. 供应商回复经 UC-01 进入，系统抽取确认的交期。
4. 交期按时：记录，流程结束。

**扩展流程**

- 3a. 供应商在时限内没有回复：提醒采购员电话跟进。
- 4a. 交期延后：系统反查受影响的工单和销售订单，发出「采购交期延误」事件，通知计划和销售，触发 UC-09 重新评估交期。
- 4b. 回复里的交期含糊（如「下周左右」）：标为待确认，提示采购员问清具体日期。

**后置条件**：每张采购订单都有最新的确认交期；延期的影响范围已通知到人。

### UC-13 到货、检验、对账与付款（P4）

| 项目 | 内容 |
|---|---|
| 参与者 | 系统、仓库、来料检验员、采购员、财务 |
| 触发 | 物料到货；收到供应商发票 |
| 前置条件 | 采购订单、入库单可查 |
| 对应故事 | US-907 |

**基本流程**

1. 物料到货，来料检验员检验。
2. 检验合格，入库。
3. 供应商发票到达（邮件附件或纸质扫描），系统识别发票内容。
4. 系统做三单匹配：采购订单、入库单、发票的数量、单价、税额是否一致。
5. 一致：系统生成付款申请，财务处理。

**扩展流程**

- 1a. 检验不合格：走退货或让步接收，不进入付款；结果计入供应商的来料合格率。
- 3a. 发票识别置信度低：标出，由财务对照原件核对。
- 4a. 三单不一致：系统列出差异项，转采购员处理，处理完重新匹配。
- 4b. 分批到货：按已入库的数量匹配，剩余部分等后续到货。

**后置条件**：付款申请只在三单一致时产生；差异和处理过程有记录。

### UC-14 新供应商准入与新物料承认（P5）

| 项目 | 内容 |
|---|---|
| 参与者 | 系统、采购员、来料检验员、研发工程师、审批人 |
| 触发 | 采购员发起新供应商或新物料的申请 |
| 前置条件 | 无 |
| 对应故事 | US-908 |

**基本流程**

1. 系统按清单收集供应商的资质文件。
2. 系统检查文件是否齐全、是否在有效期内。
3. 供应商送样，来料检验员和研发检验。
4. 检验通过，走承认审批。
5. 供应商加入合格供应商名录。

**扩展流程**

- 2a. 文件缺失或过期：提示采购员向供应商补要。
- 3a. 样品检验不通过：反馈问题，等待重新送样。
- 5a. 名录里的资质文件临近过期：提前提醒采购员更新。

**后置条件**：名录里的供应商都有有效资质和承认记录。

### UC-15 人工确认与修正（所有流程共用）

| 项目 | 内容 |
|---|---|
| 参与者 | 任何业务人员 |
| 触发 | 系统起草了要外发的内容；或系统拿不准、需要人判断 |
| 前置条件 | 用户有对应客户或单据的权限 |
| 对应故事 | US-108、US-1004、US-1104、US-1105、US-1204 |

**基本流程**

1. 系统在飞书推送卡片，同时在待办中心生成一条待办。
2. 用户查看系统起草的内容和依据。
3. 用户直接确认。
4. 系统执行（发送邮件、流转到下一步）。
5. 系统记录：原稿、最终版本、确认人、时间，并计入采纳率。

**扩展流程**

- 3a. 用户修改后确认：系统保存修改前后的差异，计为「小改后采用」。
- 3b. 用户弃用，自己另写：计为「弃用」，可选填原因。
- 3c. 用户修正了系统的判断（意图、客户、关联对象、抽取字段）：修正结果加入评测集。
- 3d. 待办超过时限没有处理：提醒本人，再超时升级给上级。
- 4a. 该动作已被管理员设为自动发送：跳过第 1 至 3 步，直接执行并记录。

**后置条件**：没有任何外发内容绕过确认（除非已被明确设为自动）；每次确认都可追溯。

## 11. 风险

| 风险 | 表现 | 应对 |
|---|---|---|
| 业务系统没有接口 | 老版本 ERP、客户管理系统不开放接口，写不进去 | 读用数据库只读视图；写在第一阶段生成待导入数据由人工导入；不用 RPA |
| 报价出错 | 价格算错或发错，直接造成损失 | 价格只由代码计算；必经审批；外发必须人工确认；所有报价留痕 |
| 邮件内容杂乱 | 多意图、长引用、转发、中英文混写、附件格式各异 | 先去引用再处理；多意图分类；低置信度进人工队列 |
| 关联错误 | 邮件挂错商机，后面全部跟着错 | 优先用单号精确匹配；关联结果可一键改正 |
| 业务人员不用 | 继续用 Excel 和个人邮箱，系统数据不完整 | 从最痛的环节切入；在飞书里一键确认；让业务骨干参与评测 |
| 流程因人而异 | 不同销售的报价和跟进习惯不同，规则难统一 | 先固化主流程，例外走人工，不追求一次覆盖所有情况 |
| 数据安全与合规 | 客户图纸、价格泄露；邮件涉及个人信息 | 内网私有模型；按角色控制可见范围；全量审计；不自动登录客户平台 |
| 范围失控 | 想一次做完销售加采购全部流程 | 严格按阶段交付，每个阶段有独立价值和验收标准 |
