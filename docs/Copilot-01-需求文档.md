# 经营与人力数据分析 Copilot：需求文档（User Story）

> 版本：2026-10-06（实现后更新了每条故事的状态）
> 对象：产品、开发、测试、技术讲解
> 背景企业：科朗这类微特电机制造企业（罩极、贯流、无刷、步进、伺服、减速电机，分家电和智能驱控两个事业部）
> 本地对照环境：MiniERP（本仓库），用它的表、视图和模拟数据当开发与评测的数据源

---

## 1. 为什么要做

| 现在的问题 | 具体表现 | 做完以后 |
|---|---|---|
| 取数靠人 | HR、财务、车间要一个数，得找 IT 写 SQL 或者从 ERP 导 Excel 再手工透视 | 用一句话问，系统给出数字、图表和所用口径 |
| 制度难查 | 考勤、请假、报销制度散在公告和文档里，同样的问题 HR 每天答很多遍 | 员工自己问，回答带原文出处 |
| 口径不一致 | "加班率""人均产值""毛利率"各部门算法不同，会上对不上数 | 每个指标只有一个定义，看板和问数用同一套 |
| 敏感数据外泄风险 | 薪资、成本、毛利一旦被随手导出就失控 | 按角色控制能看什么，全部留痕，导出要确认 |
| 只看到结果看不到原因 | 看板显示毛利下降，但不知道是销量、价格还是成本造成的 | 一句"为什么"就能按因素拆开 |

**一句话目标**：让业务人员不写 SQL 就能安全地拿到口径一致的数字，并能追问原因。

## 2. 用户角色

| 角色 | 代表人物 | 对应系统角色 | 最关心什么 |
|---|---|---|---|
| 普通员工 | 一线操作工、文员 | 各业务角色 | 制度怎么规定、自己的假期和工资条 |
| HR 专员 | 人事专员 | HR | 人数、入离职、考勤、加班、计件工资 |
| HR 经理 | 人力资源部负责人 | HR | 流失率、人工成本、编制是否超 |
| 生产管理 | 车间主任、生产经理 | PRODUCTION | 本产线的人效、出勤、加班、良率 |
| 财务 | 成本会计、财务经理 | FINANCE | 成本、毛利、回款、人工成本入账 |
| 销售 | 销售经理 | SALES | 订单、发货、回款（不能看成本和毛利） |
| 管理层 | 总经理、CFO | MANAGEMENT | 全局经营指标、异动原因、预警 |
| 系统管理员 | IT 负责人 | ADMIN | 权限配置、审计、系统稳定 |
| AI 开发与评测 | 开发团队 | — | 口径维护、评测集、Bad Case |

## 3. 范围

**要做的**

1. 制度问答（基于制度文档的 RAG）
2. 自然语言问数（Text2SQL）
3. 多轮追问
4. 归因下钻、测算与预警
5. 图表生成与报表导出
6. 经营与人力数据分析看板
7. 权限、脱敏与审计
8. 指标口径与知识库管理
9. 效果评测与持续优化

**不做的**

- 不通过对话修改任何业务数据（不新增、不修改、不删除、不审批）。
- 不做预测模型（销量预测、离职预测）。测算只做"按给定假设重新计算"。
- 不替代 ERP 里的正式报表和财务报告，只做分析辅助。
- 招聘和驻场管理不在范围内。科朗是制造企业，没有人员驻场业务；ERP 里也没有招聘模块。

## 4. User Story

格式说明：

- **故事**：作为〈角色〉，我想要〈做什么〉，以便〈得到什么价值〉。
- **验收标准**：满足这些条件才算做完。
- **优先级**：P0 必须有；P1 应该有；P2 可以后做。
- **实现状态**：本仓库里做到了哪一步（2026-10-06 更新）。实现细节和评测结果见 [实现说明](Copilot-04-实现说明与评测结果.md)。

## 5. 非功能需求

| 类别 | 指标 | 目标 |
|---|---|---|
| 响应速度 | P95 首字响应 | ≤ 1.5 秒 |
| 响应速度 | 看板首屏 | ≤ 3 秒 |
| 成本 | 单次分析 Token 消耗 | ≤ 6k |
| 准确性 | SQL 执行成功率 | ≥ 95% |
| 准确性 | 指标口径一致率（和口径库定义一致） | ≥ 95% |
| 准确性 | 结果准确率（和标准答案一致） | ≥ 90% |
| 覆盖 | 分析模板覆盖常见意图的比例 | ≥ 75% |
| 安全 | 越权查询、写操作被拦截的比例 | 100% |
| 安全 | 查询审计覆盖率 | 100% |
| 可用性 | 单次查询返回行数上限 | 1,000 行 |
| 可用性 | 单条 SQL 执行超时 | 10 秒 |

> 说明：P95 是把 100 次请求按耗时从小到大排，第 95 个的耗时。它比平均值更能反映"慢的时候有多慢"。

| # | 意图 | 示例问题 | 主要数据来源 |
|---|---|---|---|
| 1 | 制度问答 | 迟到多久算旷工？病假工资怎么发？ | 制度文档库 |
| 2 | 人员与编制 | 现在各部门多少人？劳务派遣占比多少？上月谁离职了？ | `v_employee`、`v_employee_change`、`v_dept` |
| 3 | 考勤工时 | 伺服线上月出勤率多少？哪个班组加班最多？ | `v_attendance`、`v_leave` |
| 4 | 薪酬与计件 | 上月计件工资总额多少？有多少人拿的是保底？ | `v_payroll`、`v_payslip`、计件单价 |
| 5 | 生产与人效 | 各产线人均产值排名？L5 线良率最近三个月的趋势？ | `v_wo_report`、`v_work_order`、考勤 |
| 6 | 成本与毛利 | 三季度伺服系列毛利率多少？为什么比二季度低？ | `v_sales_fact`、`v_price_variance` |
| 7 | 回款与结算 | 哪些客户应收逾期？本月回款多少？ | `v_sales_invoice`、`v_receipt` |
| 8 | 多轮追问 | （接上一问）那步进线呢？换成按季度看。 | 继承上一轮 |

在这之上，系统把意图归成三个大类来决定走哪条处理路线：

| 大类 | 包含的意图 | 处理路线 |
|---|---|---|
| 制度问答 | 1 | 文档检索 → 带引用回答 |
| 经营问数 | 2–7 | 口径检索 → 生成 SQL → 校验 → 权限 → 执行 → 图表 |
| 测算预警 | 归因、测算、预警订阅 | 调用专门的计算工具 |

## 7. 敏感数据分级

| 级别 | 字段 | 处理方式 |
|---|---|---|
| 个人身份信息 | 身份证号、银行卡号、手机号 | 打码，只显示首尾 |
| 薪酬 | 基本工资、计件工资、应发、实发、社保基数 | 只对 HR、财务、管理层开放；其他角色整列不返回 |
| 成本 | 产品成本、单位成本、采购价、转换成本 | 只对财务、管理层开放 |
| 经营结果 | 产品毛利、客户毛利、毛利率 | 只对财务、管理层开放；销售角色不可见 |
| 一般业务数据 | 订单、发货、库存数量、考勤汇总 | 按角色的表级和行级权限控制 |

## 8. 术语表

| 术语 | 白话解释 |
|---|---|
| Copilot | 副驾驶。指陪着人一起干活的 AI 助手，人做决定，它帮忙查和算 |
| RAG | 先从资料库里找到相关内容，再让大模型基于这些内容回答，减少编造 |
| Text2SQL | 把自然语言问题转成数据库查询语句 |
| 意图识别 | 判断用户这句话想干什么（查制度、查数据、还是做测算） |
| 槽位 | 问题里的关键信息格子，比如指标、时间、产线 |
| 口径 | 一个指标到底怎么算的规则 |
| 原子指标 | 直接从数据里数出来的指标，比如加班工时 |
| 派生指标 | 用原子指标算出来的指标，比如加班率 = 加班工时 ÷ 应出勤工时 |
| 归因下钻 | 把一个变化拆成几个原因，并逐层往细处看 |
| RBAC | 按角色分配权限 |
| 脱敏 | 把敏感信息部分遮住或整列隐藏 |
| 审计日志 | 记录谁在什么时候做了什么，供事后检查 |
| Bad Case | 系统答错的例子，用来分析和改进 |
