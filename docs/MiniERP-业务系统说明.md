# MiniERP：微特电机制造企业一体化业务系统

模拟一家微特电机厂（罩极 / 贯流 / 无刷 / 步进 / 伺服 / 减速电机，家电与智能驱控两个事业部）的核心业务系统，覆盖 **ERP（主数据、销售、采购、库存、财务）+ PLM（BOM 版本、工程变更 ECN、技术文档、新产品开发 NPI）+ SRM（供应商绩效、询价比价定标）+ CRM（商机管道、跟进、联系人）+ WMS（库位上架/拣货）+ MES（工单、报工）+ APS（有限产能排产）+ QMS（来料检验、客诉 8D）+ GL 总账（自动凭证、科目余额表、利润表、存货对账）+ BI 经营看板**。

项目内置一个**逐日业务模拟器**：生成 2024-10 至 2026-09 两年的业务数据，每一笔都通过真实的业务服务完成，所以库存、成本、应收、应付之间的勾稽关系一致。这份数据后续可以直接作为**财务经营分析 Agent（Text2SQL / 指标口径 RAG / 归因分析）**的数据源。

> 客户、供应商均为虚构名称，数据为模拟生成。

## 快速启动

```bash
docker compose up -d --build
```

- 前端：http://localhost:5180
- 后端 API：http://localhost:8080/api
- MySQL：`localhost:3307`，库名 `minierp`，账号 `minierp` / `minierp`

首次启动时自动建表（Flyway），并生成两年模拟数据，大约需要 2～3 分钟。进度可以通过 `docker compose logs -f backend` 查看。要重新生成数据，执行 `docker compose down -v` 后再启动即可。

网络受限时可以指定 npm 镜像源：`NPM_REGISTRY=https://registry.npmmirror.com docker compose up -d --build`

**本地开发**：`docker compose up -d mysql` 启动数据库；后端用 IDE 运行 `MiniErpApplication`（需 JDK 21，环境变量 `DB_PORT=3307`）；前端执行 `cd frontend && npm install && npm run dev`，默认把 `/api` 代理到 8080。

## 业务流程

```
销售：订单(草稿) → 确认(信用额度检查) → 发货(扣成品库存，按移动加权平均计成本) → 开票(应收) → 收款
采购：采购单 → 确认 → 到货(待检) → IQC(抽样不良率 ≤ 2% 合格入库，否则整批判退) → 收票(应付，按合格数量) → 付款
生产：MPS 按"未发订单 + 安全库存 − 总仓库存 − 在制"生成工单 → 下达 → 报工(按 BOM 倒冲领料，主料不足自动用替代料，完工入库，报废损失摊入良品成本)
组件：按半成品低阶码逐层计算"上级工单需求 + 安全库存 − 半成品库存 − 在制组件工单"，下达组件工单（伺服：转子铁芯 → 转子/定子组件 → 成品）
采购计划：MRP 按"在制工单需求（展开到外购件）+ 10 天安全库存 − 库存 − 在途"生成采购单
收票：三单匹配（订单价 vs 发票价）→ 价差 ≤ 3% 直接记账，> 3% 财务审批（批准记账 / 驳回重开）
调拨：新建 → 发出（转入调拨在途）→ 到货；前置仓按订货点法（低于 7 天需求补到 14 天）自动生成补货调拨单
质量：客诉 OPEN → ANALYZING → CLOSED（关闭前必须填写根本原因和纠正措施）
费用：提交 → 财务审批（不能审批本人提交的报销单）
ECN：草稿 → 提交会签（研发/生产/质量/采购四方，申请人不能会签，任一否决即否决）→ 批准 → 发布
     发布时每个受影响产品生成新 BOM 版本（A→B…），旧版本作废，生产用 BOM 同步更新
NPI：概念 → 设计 → 样机 → 试产 → 量产，每个阶段门评审 GO / HOLD / KILL
```

## 业财一体化与仓储

- **自动凭证**：发货、开票、收款、IQC 入库、收票、付款、报工、报销审批、库存调整，都在业务事务内调用 `GlService.post` 生成凭证。记账前 `VoucherValidator` 校验借贷平衡，不平衡则整笔业务回滚。
  - 已验证：两年约 2.6 万张凭证全部平衡；总账收入、应收与销售发票子账分文不差。
  - 存货总账与库存子账的差异约为万分之 0.2，来自移动平均单价的舍入，存货对账页面会展示这个差异。
- **月结**：
  - 结账前校验试算平衡，然后结转制造费用差异（计入主营业务成本）、结转损益到本年利润；12 月再把本年利润转入未分配利润。
  - 期间必须按顺序结账，已结期间禁止记账；反结账只能从最后一个已结期间开始，会删除该期的结转凭证。
  - 模拟器每月初自动结上月账，两年共 24 个期间已结。
- **应付暂估**：检验入库时按订单价贷记"应付账款-暂估"，收到发票时冲回暂估、确认正式应付（价税合计）。总账与子账对账覆盖原材料、半成品、库存商品、调拨在途、应收、应付、暂估。
- **采购价差**：发票价 ≠ 订单价时，价差 = 发票金额 − 暂估金额。
  - 按"到货批次仍在库的比例"拆分：在库部分调整存货成本（1403，同时重算移动平均单价），已领用部分计入主营业务成本（6401）。这是实际成本法下的做法，拆分比例直接取自批次数据。
  - 价差率超过 3% 的发票先挂起（不记账、暂估不冲回），财务批准后按审批日的在库比例记账；驳回则发票作废，等供应商重开。
  - 模拟数据里，铜线和磁钢按开票月"点价"（供应商到货后 5~12 天开票）：下单与开票跨月时，价格指数的变化就是价差，2025 下半年稀土涨价、2026 年铜价上涨都会反映到采购价差报表。
- **多仓库与调拨**：原材料仓、半成品仓、成品总仓（深圳），以及华东前置仓（苏州）、香港出口仓。
  - 每个仓库独立核算现存量与移动平均成本，批次和库位也按仓库管理（库位编码带仓库前缀）。
  - 调拨发出：调出仓按移动平均出库，Dr 1402 调拨在途 / Cr 存货；到货：调入仓按发出成本入库，Dr 存货 / Cr 1402。在途期间货物不在任何仓库，由 1402 承接，所以总账和库存账始终对得上。
  - 批次随货转移：调入仓按调出时消耗的批次原样重建（批次号、供应商、原入库日期不变），先进先出不被打乱，追溯链跨仓不断。
  - 发货选仓：客户所在区域有前置仓、且前置仓整单有货时就近发货，否则从总仓发，避免拆单（`WarehouseRouter`）。
  - 补货：前置仓按近 28 天区域发货量算日均需求，订货点法生成调拨建议（`ReplenishmentCalculator`），模拟器每周一、周四自动补货。
- **批次与追溯**：
  - 原材料批次号 = 到货单号，成品批次号 = 工单号；出库按先进先出消耗批次，并记录消耗单据。
  - 反向追溯：客诉 / 发货单 → 成品批次 → 所用原材料批次 → 供应商、IQC 结果。
  - 正向追溯：原材料批次 → 用到它的工单 → 发货单 → 客户，得到召回 / 排查清单。
  - 多级 BOM 下，半成品批次号 = 组件工单号，反向追溯逐层展开（成品批次 → 转子组件批次 → 转子铁芯批次 → 硅钢片到货批次），正向追溯逐层向上找到成品工单。
- **WMS**：`InventoryService` 每次入库调用上架（同物料集中存放，新物料放最空的库位），每次出库调用拣货（先拣零散库位）。Σ库位库存 = 仓库现存量，页面上可以一键校验。
- **多级 BOM 与替代料**：
  - 成品 BOM（`md_bom`）+ 半成品 BOM（`md_material_bom`）构成多级结构。`BomExploder` 做逐层展开、同料合并、低阶码计算和循环引用检测；"多级 BOM 展开"页面按树形展示每层用量、现存量和卷积成本。
  - 半成品是 `supply_type = MAKE` 的物料，有自己的产线、加工费、经济批量；组件工单产出进半成品仓，记 1411 自制半成品，上层工单领用时贷记 1411。
  - 替代料按优先级和替代比例配置（1 主料 = ratio 替代料，可用于铜线换铜包铝这类按重量折算的场景）。生产倒冲时主料不够才用替代料（`SubstituteAllocator`），每次替代都记在替代料使用记录里。
- **APS**：
  - 按物料低阶码分层，从最底层组件开始逐层排产。每层先做齐套检查：工单按交期顺序依次占用 ① 主料现存量 ② 替代料现存量 ③ 主料在途采购 ④ 替代料在途，得到最早齐套日和状态（齐套 / 等待到货 / 缺料）。
  - 下层组件工单排出的计划完工日，作为上层工单的"在途供应"放回资源池，所以成品工单不会早于它的组件完工开工。组件工单交期 = 上级工单交期 − 2 天。
  - 每层按产线日产能做有限产能排产，交期最早优先（EDD），缺料工单让位给已齐套的工单。
  - 输出甘特图、负荷率、延期 / 缺料 / 替代料预警。
- **SRM**：月度绩效由 IQC 合格率（50 分）、准时交付率（30 分）、价格指数（20 分）组成，连续两个月 D 级自动转为"观察"状态。询价比价按价格、交期、绩效综合推荐；选择非推荐供应商时必须填写理由，定标后自动生成采购单。
- **CRM**：商机按阶段逐级推进，丢单必须填写原因，另有漏斗统计。

## 组织、OA 与 HR

- **组织与统一身份**：
  - 部门树（14 个部门，按部门归集人工成本）、岗位职级、员工档案，以及入职、转正、调岗、调薪、离职的异动记录。
  - 系统账号挂在员工上：员工离职生效时自动停用账号。`JwtAuthFilter` 每次请求都会检查账号是否仍启用（60 秒缓存），所以旧 token 最多 60 秒后失效。
  - 汇报关系由 `OrgChart` 计算：档案里指定了直属上级就用它，没有就取部门负责人；本人就是负责人时，向上找上级部门的负责人。
- **OA 流程引擎**（自研，`com.minierp.workflow`）：
  - 流程定义用 JSON 描述节点，按版本管理，运行中的实例继续按发起时的版本执行。
  - 审批人类型：直属上级（可指定第几级）、申请人部门负责人、指定部门负责人、角色、指定账号；每个节点可设或签 / 会签和进入条件。
  - 进入条件用 `ConditionEvaluator` 解析，例如 `amount >= 5000 && days > 3 || leaveType == 'SICK'`。它是一个小解析器，不用脚本引擎，不存在表达式注入。
  - 发起时由 `WorkflowRouter` 算出整条审批路线：条件不满足的节点不进入；申请人本人自动跳过，满足职责分离；前序节点已审批过的人自动去重。
  - 办理操作：同意、驳回（必须填理由）、转交、加签（加签人必须同意）、撤回（还没人同意时才能撤回）。节点是否通过由 `NodeDecision` 判定。
  - 流程结束时在同一事务内发布 `WorkflowFinishedEvent`，由业务模块完成后续动作：报销入账（按审批通过日记账，避免跨月落到已结账期间）、请假写入考勤、离职登记最后工作日、工资计提。
  - 内置 7 个流程：请假、费用报销、出差、用印、离职、工资发放、通用审批。前端有审批中心（待办 / 已办 / 我发起的，路线步骤条 + 审批时间线）、公告、流程定义编辑（保存即生成新版本），顶栏显示待办数。
- **HR**：
  - 考勤日记录：正常、迟到、旷工、请假，含加班工时；请假审批通过后自动写入考勤。
  - 计件工资：各产线的计件单价按报工日期取有效单价，只计良品；班组当月计件总额按组员出勤工时（含加班）分摊（`PieceWageAllocator`，用最大余数法处理分摊尾差）。
  - 月度工资（`PayrollCalculator`）：
    - 月薪：按在职天数折算，扣事假和旷工。
    - 计件：不足保底工资的按出勤补足；加班产量已经计件，只另付 0.5 倍加班溢价。
    - 社保公积金按缴费基数的上下限计算。
    - 个税用累计预扣法（`IncomeTaxCalculator`）。
  - 工资流程：核算 → 工资发放审批（人力负责人 → 财务负责人 → 总经理）→ 计提入账：按部门成本类型借记制造费用、销售费用、管理费用或研发费用，贷记应付职工薪酬。
  - 次月 10 日发放：实发工资和社保公积金从银行付出，同时代扣代缴个税。总账对账里新增应付职工薪酬。
  - HR 看板：人数、入离职、流失率趋势、出勤率、人工成本按费用归集、各产线人均工资、加班和单位人工成本。
- **业财影响**：以前的模拟数据只有加工费通过制造费用转进成本，从来没有实际人工成本记进来，所以利润偏高。现在实际发生的工资进入制造费用，月结时制造费用差异结转到主营业务成本；职员工资按部门进入期间费用。生产、质量、仓储部门的报销和车间水电费也改为计入制造费用。

## 设备、MES 与质量深化

- **EAM 设备管理**：
  - 设备台账共 47 台，每台都有关键度，以及“停机时损失产线产能的比例”，瓶颈设备为 100%。
  - 故障维修流程：报修（同时在产线拉设备安灯）→ 派工 → 完工。完工时领用的备件从库存出库，记入制造费用（借制造费用、贷原材料）。
  - 预防性保养：按计划生成保养单，下次到期日自动顺延到工作日。
  - 可靠性指标：MTBF、MTTR、固有可用度（`ReliabilityCalculator`）；设备看板展示故障趋势、停机 TOP 设备和故障代码分布。
  - 模拟里，设备停机会按损失比例压低当天产线产量，所以设备问题会一路传导到交付和 OEE。
- **MES 深化**：
  - 工艺路线：各系列和各类半成品的工序、标准工时、关键工序、检验点。
  - 班次结算：每条产线每天计算 OEE（`OeeCalculator`：时间开动率 × 性能开动率 × 合格品率；理论产能 = 单班产能 × 班次），以及劳动效率（产出折算的标准工时 ÷ 考勤工时）。
  - 测试台数据接入：伺服整机序列号加出厂测试值（反电势、空载电流、编码器零位、绝缘电阻、振动）。出货时按先进先出把序列号绑到发货单，可以单台追溯到工单批次、物料批次和客户。
  - 首检和巡检，不合格自动拉质量安灯；缺料停线自动拉缺料安灯，恢复报工时关闭；安灯记录响应和解决时长。
  - 产线日产能改为“单班产能 × 班次”，APS 也按这个口径排产。原来只算了一个班，这也是之前延期工单偏多的原因之一。
- **QMS 深化**：
  - 8D：中、高严重度客诉进入分析阶段时自动开 8D，D1–D3 自动带出；客诉关闭时补齐 D4–D8 并结案。
  - SPC：从出厂测试数据按天抽子组，画均值-极差控制图，计算 Cp、Cpk、Ppk，并按 Western Electric 规则判异：超出控制限、连续 9 点在中心线同侧、连续 6 点持续上升或下降（`SpcCalculator`）。页面上还有月度 Cpk 走势。
  - PFMEA：严重度 × 频度 × 探测度得出 RPN 和措施优先级，并记录改进后的 RPN（`FmeaCalculator`）。
  - 量具校准：按周期校准，不合格的停用报废，记录逾期天数。
  - 出货检验：按 GB/T 2828.1 一般检验水平 II、正常一次抽样。由批量查样本量字码，再按 AQL 查主表；遇到箭头时改用箭头指向的方案，样本量随之改变（`AqlSampling`）。

## 研发协作与知识库

- **研发项目管理**（类似 Jira，`com.minierp.pm`）：
  - 基本对象：项目（迭代 SCRUM / 看板 KANBAN）、迭代、问题（史诗、需求、任务、缺陷）、评论、工时、问题关联。
  - 状态流转由 `IssueWorkflow` 校验：
    - 需求和缺陷必须经过评审才能完成，任务可以直接完成。
    - 没开始的问题只能以“不修复 / 重复”关闭。
    - 任务完成后不能重新打开。
    - 史诗下还有未完成的问题时，史诗不能关闭。
  - 状态、经办人、迭代的每次变化都写入历史表；燃尽图（含迭代中途加入的范围）、速率与预测区间、周期时间 p50 / p85 / p95、累积流图都从历史表计算（`AgileMetrics`）。
  - 看板支持拖拽卡片改状态；另有待办池、史诗进度和度量页。
  - 和其他模块打通：
    - 新品开发项目启动时自动建研发项目，项目暂停或结项后停止开新迭代并归档。
    - 中、高严重度客诉进入分析时，自动在对应产品系列的平台项目里生成缺陷；客诉 8D 结案时缺陷随之关闭。
  - **研发费用按项目归集**：研发人员当月人工成本（取自工资表）按项目工时 ÷ 出勤工时分摊，未登记到项目的计入“非项目”（`RndCostAllocator`）。这就是研发费用加计扣除需要的项目辅助账。
- **知识库**（类似 Confluence，`com.minierp.kb`）：
  - 5 个空间：制度流程、工艺技术、质量经验、设备维修、研发设计。
  - 页面树、Markdown 编辑与实时预览、草稿 / 发布；每次保存生成一个新版本，历史版本可以按行对比（`TextDiff`，基于最长公共子序列）。
  - 中文全文检索：MySQL 的 FULLTEXT 索引加 ngram 分词。
  - **经验自动沉淀**：
    - 8D 结案 → 质量经验页。
    - ECN 发布 → 设计变更说明页。
    - 同一设备一个月内故障两次及以上 → 设备故障案例页，每月追加新版本。
    - 工艺路线 → 作业指导书；审批流程定义 → 审批权限说明。
  - **进入 RAG**：技术助手“同步知识库页面”按页面版本增量导入 Milvus；知识库更新后，技术助手也能回答“这个问题以前怎么处理的”。

## 固定资产、资金预算、合同与关务

- **科目表修正**：按企业会计准则，6603 改为财务费用，研发费用改用 6604。新增税金及附加 6403、资产处置收益 6115，以及固定资产、累计折旧、固定资产清理、应收出口退税、增值税的出口退税 / 出口抵减 / 未交增值税等明细科目。损益结转和利润表同步更新。
- **固定资产**：
  - 期初约 80 项资产，包括房屋、生产设备（与设备台账一一关联）、公用工程、模具、车辆和电子设备。
  - 折旧规则（`DepreciationCalculator`）：年限平均法 / 双倍余额递减法（最后两年改为直线法）；当月增加的次月起提，当月减少的当月照提；按“计划累计 − 已提累计”计算每月金额，四舍五入误差不会累积。
  - 折旧按使用部门分别计入制造费用、销售费用、管理费用或研发费用。有了生产设备和厂房折旧，制造费用差异基本消除。
  - 资本性支出走 OA 审批：部门负责人 → 设备动力部 → 财务负责人 → 总经理（≥20 万），审批通过后自动入账建卡（设备进项税可抵扣）。
  - 处置时通过“固定资产清理”结转，差额计入资产处置收益。
  - 月结前校验当期折旧已经计提。
- **资金**：
  - 期初银行存款 8,000 万。网银流水逐笔导入；约 25% 的对外付款会晚 1–3 个工作日才出账；银行季度结息、月末扣手续费，次月依据银行回单入账，入账时就与流水匹配。
  - 月末银行对账（`BankReconciler`）：
    - 先按“金额 + 附言（发票号）”匹配（覆盖春节、国庆长假的延迟出账，也能拆开同金额的两笔付款），再按“金额相等、日期相差 ≤ 7 天”取日期最近的一笔匹配，生成余额调节表和四类未达账项。
    - 采用截至期末的口径：已匹配但另一方日期在期末之后的，仍列为本期未达账项。
  - 报销审批后记入“其他应付款”，财务每周五集中付款。
  - 13 周资金滚动预测（`CashForecaster`）：应收按客户近 6 个月平均逾期天数推算回款日，应付按到期日；再加上工资、税款、出口退税、日常费用；给出最低余额和低于安全余额的首周。
- **预算**：
  - 按月、部门、费用类别编制预算。报销提交时检查执行后的使用率（`BudgetControl`）：≤ 90% 正常，90%–100% 预警，> 100% 超预算，报销流程自动加一个“超预算审批（总经理）”节点。
  - 这个节点和“≥5 万总经理审批”是同一个人时，审批人去重规则会自动合并，不会让总经理审两次。
- **合同**：
  - 类型：销售框架、采购框架、服务、保密协议。流程：起草 → OA 审批（部门负责人 → 财务 ≥50 万 → 总经理 ≥200 万）→ 生效（审批日即签订日）→ 到期（设了自动续约的顺延一年）。
  - 框架合同的履约额取合同期内对该客户的开票额，或对该供应商的收票额，从而得到履约率；每年 12 月按本年实际额乘以增长预期，签下一年的框架合同。
- **关务与增值税**：
  - 外销发货自动生成报关单：按产品系列和功率归类 HS 编码（`HsClassifier`），经放行、结关，退税按结关月申报。
  - 增值税月结按生产企业免抵退税计算（`ExportRefundCalculator`，财税〔2012〕39 号口径）：
    - 先算“不得免征和抵扣税额”，做进项转出；再算当期应纳税额、免抵退税额，最后拆成应退税额和免抵税额，剩余部分为期末留抵。
    - 记账后，增值税各明细科目余额结转到“未交增值税”（贷方为应纳，借方为留抵）。
    - 按“应纳 + 免抵税额”的 12% 计提城建税和教育费附加。
    - 次月 15 日缴纳；出口退税款约 60 天后到账。
    - 月结前校验本月已完成增值税月结。
  - 模拟公司以内销为主，每月都是应纳为正，所以出口部分全部表现为“免抵”，而不是“退税”，这和大多数内外销兼营的制造企业一致。

## 售后服务、IT 服务台与安环能源

- **售后服务**：
  - 保修按序列号判定：伺服 18 个月、其他产品 12 个月，自发货日起算（`WarrantyPolicy`）。输入 SN 可带出生产工单、出厂测试、客户、发货和历史工单。
  - 服务工单按优先级计 SLA（`SlaClock`）：P1（客户停线）7×24 响应 2 小时、解决 24 小时；P2、P3 按工作时间（工作日 8:30–17:30，跳过节假日）计。处理方式分远程、上门、返厂（RMA）、无故障；上门产生差旅报销。
  - RMA 有两个来源：
    - 单台工单：先换后修，开出 RMA 即算工单解决；
    - 中高严重度客诉：批量退回。
  - RMA 退回后检验处置：
    - 换新：成品出库，但成品库存不到退货量 3 倍时改为维修，避免挤占正常发货；
    - 维修：按故障类型领用 BOM 里的对应部件（异响换轴承、编码器故障换编码器等）；
    - 无故障：原样退回。
  - 质量保证金（预计负债 2801）：
    - 期初 30 万，每月按主营收入 × 计提比例计提；
    - 保内换新、维修成本和客户索赔（停线损失、挑选返工费）冲减保证金；
    - 年末按“近 12 个月索赔 ÷ 12 × 在保平均剩余月数”测算应有余额，补提或冲回，并按索赔率 × 1.1 确定下年计提比例。上线不足 12 个月的年度不作调整。
    - 月末余额低于近 3 个月索赔额时补提差额，批次质量问题集中索赔时预计负债不会出现借方余额。
  - 保外维修向客户收服务费（其他业务收入 6051 + 销项税），耗用部件计其他业务成本 6402，利润表的营业收入 / 营业成本同步包含这两项。月结前校验当月已计提质量保证金，总账与子账对账增加 2801。
- **IT 服务台**：
  - 故障与服务请求：优先级由影响范围 × 紧急程度矩阵决定（`PriorityMatrix`，P1~P4）；P1 按 7×24 计时（响应 0.5 小时、解决 4 小时），其余按工作时间计时。
  - 变更走 OA 流程 IT_CHANGE：信息部负责人审批，高风险变更加总经理审批；审批通过后实施、关闭，并可关联引发它的故障。每月补丁、每季度 ERP 发版都走变更。
  - CMDB 登记服务器、网络、打印机、MES 终端和每位职员的笔记本，服务器与固定资产卡片关联。
  - 入职自动开服务请求：领用库存笔记本、分配全员许可和部门许可，席位不足时记在工单里；离职时回收电脑（满 4 年报废）、释放许可。
  - 软件许可合规：适用范围内的在职人数与席位对比，列出待分配人数；许可到期续费走报销（信息部 软件服务费）。
- **安全环保**：
  - 隐患排查治理：安环部每周二巡检，员工随手拍，事故后专项检查。一般隐患 7 天、重大隐患 30 天整改，整改后由安环部复查，不通过的重新整改。
  - 事故与未遂事件按海因里希金字塔分为未遂、急救、可记录、损工四级；可记录和损工事故必须填写根因和整改措施才能关闭。
  - 安全绩效（`EhsRules`）：LTIFR = 损工事故 × 10⁶ ÷ 工时，TRIR = 可记录事故 × 2×10⁵ ÷ 工时，严重率 = 损失工日 × 10⁶ ÷ 工时，工时取自考勤。
  - 危险作业许可（动火、高处、受限空间、临时用电）走 OA 流程 EHS_PERMIT：部门负责人 → 安环部 → 受限空间或一级动火加总经理审批；作业结束后关闭作业票。
  - 危险废物台账：HW08、HW12、HW49 按月产生，按季度转移（生成联单号、处置费走报销）。按先进先出计算最早一批的贮存天数，超过 270 天预警，超过 365 天违规（固废法：贮存不得超过一年）。
- **能源**：
  - 电表：8 条产线、空压站、中央空调、伺服老化房、办公研发楼、宿舍。每天读数按产线产出、班次时段、季节生成，并分到尖 / 峰 / 平 / 谷各时段。
  - 分时电价（`TouTariff`）按广东工商业口径：峰 10–12、14–19 点，谷 0–8 点，峰平谷比价 1.7 : 1 : 0.38，7–9 月 11–12、15–17 点执行尖峰（峰段 × 1.25）。
  - 月度账单 = 电度电费 + 基本电费（2500 kVA 变压器）+ 水费，同时给出综合电价、碳排放（0.5366 kgCO₂/kWh）和单位产品电耗。账单金额走“生产部 水电费”报销流程付款，替代了原来随机生成的水电费，超预算照样触发总经理审批。

## 日志与开放接口

- **日志**：
  - ERP 后端用 SLF4J + Logback，技术助手用 loguru，两边格式一致：时间 | 级别 | 追踪号 | 位置 - 消息。
  - 每个请求一个追踪号（请求头 `X-Trace-Id`）。前端每次请求都生成，后端和技术助手沿用并写进每一行日志，再通过响应头和错误响应体返回；前端报错提示里会带上它，拿它 `grep` 就能找到这次请求在两个系统里的全部日志。MCP 工具调用 ERP 时也会带追踪号。
  - 访问日志记录方法、路径、状态、耗时和用户，慢请求（后端 ≥ 1s）记 WARN。业务校验失败记 WARN，不打堆栈；系统异常记 ERROR，带堆栈。
  - 后端日志按天滚动（单文件 100MB、保留 14 天），WARN 及以上另写 `minierp-error.log`（保留 30 天）。文件在宿主机 `logs/backend/`，重建容器不会丢；技术助手的日志在 `assistant/logs/`。
- **REST API**：交互文档在 http://localhost:8080/swagger-ui.html，机器可读版本在 `/v3/api-docs/minierp`（目前约 100 个接口）。
  - 认证：先 `POST /api/auth/login` 拿 JWT，之后带 `Authorization: Bearer`，权限按角色。
  - 通用只读查询：`GET /api/views` 返回当前角色可访问的数据集目录（中文说明、可过滤列、日期列），`GET /api/views/{key}` 分页查询。
- **MCP 服务**（`assistant/app/api/mcp/erp_mcp_server.py`）：把 ERP 能力开放给 Claude、技术助手和后续的分析 Agent。
  - 采用网关模式：工具不直连数据库，而是调用 ERP REST API，沿用用户自己的角色权限、敏感列裁剪和审计日志。例如销售账号调用对账工具，会返回 403 和追踪号。
  - 38 个工具：
    - 只读：`list_datasets`、`query_dataset`、`get_stock`、`trace_lot`、`trace_complaint`、`bom_tree`、`latest_production_plan`、`gl_reconciliation`、`income_statement`、`monthly_kpis`、`my_pending_approvals`、`approval_detail`、`find_employee`、`hr_dashboard`、`shop_floor_board`、`serial_trace`、`spc_analysis`、`equipment_reliability`、`aql_sampling_plan`、`search_knowledge`、`get_knowledge_page`、`rd_project_status`、`fixed_assets_overview`、`bank_reconciliation`、`cash_forecast`、`budget_execution`、`find_contracts`、`vat_returns`、`after_sales_overview`、`warranty_lookup`、`it_service_overview`、`ehs_overview`、`energy_report`
    - 发起类：`create_sales_order_draft`、`create_transfer_draft`、`submit_leave_request`、`create_rd_issue`、`create_it_ticket`。只生成草稿、提交报修或发起审批；确认、发出、批准都要人在 ERP 里操作，所以 MCP 没有开放审批工具。
  - 启动：`cd assistant && uv run python -m app.api.mcp.erp_mcp_server`，默认监听 `http://127.0.0.1:8092/mcp`；客户端请求头带 `Authorization: Bearer <ERP JWT>`。
  - 本机桌面客户端可以用 stdio 模式：加 `--transport stdio`，身份取环境变量 `MINIERP_TOKEN`，或 `MINIERP_SYNC_USER` / `MINIERP_SYNC_PASSWORD`。

## 设计要点（面试可讲）

- **库存并发与成本**：所有出入库都经过 `InventoryService`，用 `SELECT … FOR UPDATE` 行锁把同一物料的出入库串行化，防止超卖，同时保证移动加权平均成本计算正确；`inv_stock` 现存量和 `inv_txn` 流水在同一事务内更新。
- **单据号并发安全**：用 MySQL 的 `LAST_INSERT_ID(expr)` 技巧按"前缀 + 日期"生成流水号，一条语句完成原子自增。
- **通用查询层 + 白名单**：列表页统一走 `/api/views/{key}`。可过滤、可排序的列都在 `ViewRegistry` 里声明，其余参数一律忽略，防止 SQL 注入；按角色限制可访问的视图，并在服务端裁剪成本、毛利等敏感列。
- **RBAC 与职责分离**：`@PreAuthorize` 做方法级授权；关键规则写在服务层，比如信用额度检查、先检验后收票、不能审批本人报销。
- **审计日志**：`@Audited` 注解加 AOP，记录所有写操作的操作人、参数和成败，日志只追加。
- **BOM 只能通过 ECN 修改**：直接修改 BOM 的接口已移除，每一次变更都有会签记录和版本追溯。ECN 自带影响分析：单台材料成本变化、按近 12 个月销量折算的年度成本影响、在制工单数量、被停用物料的呆滞库存金额。已发布的 ECN 用"变更前后两个 BOM 版本"复算影响。
- **文档存储安全**：文件名清洗，存储路径做目录穿越校验；同一文档编号上传新文件即升版，旧版本标记为已替代。
- **视图即语义层**：`v_sales_fact`（发货行粒度的收入、成本、毛利，带客户、产品维度）是 BI 的唯一口径来源，也是后续财务分析 Agent 做 Text2SQL 的基础；所有字段都带中文 COMMENT。

2. **机器人需求增长**：机器人、工业自动化客户需求快速增长，伺服电机收入占比提升。
3. **客户回款恶化**：佛山顺德宏达电器（C003）2026 年起回款恶化，逾期累积后超出信用额度，新订单被冻结在草稿状态。
4. **磁钢来料质量下滑**：宁波恒磁（S05）2026-04 至 2026-08 磁钢来料不良率上升，IQC 判退增多，无刷和伺服电机的异响客诉增加。
5. **伺服线良率下滑**：伺服线 L5 在 2025-11 至 2026-01 因编码器装配问题良率下滑，同期出现编码器故障客诉。
6. **ECN 时间线**：2025-07 贯流风机包材降本；2025-09 步进轴承降本被质量部否决；2026-02 伺服编码器改压接端子，L5 良率随即恢复；2026-06 罩极绕组线径优化，毛利部分回升；2026-09 无刷磁钢切换加严规格，成本上升但解决异响；另有会签中、草稿各 1 张。
7. **NPI 项目**：变频空调 BLDC 平台（已量产结项）、一体化关节模组（试产）、灵巧手空心杯电机（样机）、86 闭环步进（暂停）、罩极铝线替代（设计）。
8. **季节性**：春节停产，4 月和 10 月有展会费用，夏季水电费上升。
9. **点价采购价差**：铜线、磁钢按开票月价格结算，2025 下半年稀土、2026 年上半年铜价上涨带来正向价差，其中跨月涨幅超过 3% 的发票走了财务审批。
10. **磁钢替代料**：S05 磁钢判退造成 N42SH 缺料时，伺服转子组件工单自动改用 N45SH（贵约 10%），替代记录可在"替代料使用"里按时间查看。
11. **前置仓**：华东客户和外销客户分别由苏州前置仓、香港出口仓就近发货，总仓每周两次按订货点补货。
12. **春节返岗**：2025-02、2026-02 春节后，一线约 12% 员工没有返岗，当月流失率跳升，随后按产量补招（劳务派遣约占 35%）。
13. **扩产招工**：伺服线 L5 和组件线 L7 产量增长，每周按近 28 天产量自动补招，计件工资随产量上升。2026-03 计件单价普调 5%。
14. **加班**：产线当天负荷超过 55% / 75% / 90% 时，分别安排 1 / 2 / 3 小时加班，旺季人均加班明显上升。
15. **冲床故障**：2025-06 中旬到 09 月，L8 高速冲床的模具和送料机构磨损，故障频发，转子铁芯供应跟不上，伺服组件线的 OEE 随之下滑。2025-10 起保养周期从 30 天缩短为 14 天，故障回落。
16. **编码器过程能力**：2025-11 到 2026-01，编码器零位偏差的 Cpk 从约 1.9 降到 1 以下，同期零位校准台故障增多、首检不合格率上升，和伺服线良率下滑、编码器客诉是同一件事。
17. **磁钢一致性**：2026-04 中旬到 08 月，伺服反电势波动变大、均值下移，振动上升，反电势 Cpk 下降，和 S05 判退、异响客诉、N45SH 替代料使用同期。
18. **超预算**：夏季车间水电费（空调负荷，由能源账单得出）超出按全年均值编制的预算，2026 年研发材料费实际加了 60%，预算只加了 35%，这些报销都走了总经理的超预算审批。
19. **资本性支出**：2025-03 伺服总装线二期、2025-10 高速冲床备用模具（呼应冲床故障）、2026-04 伺服自动化测试线、2026-06 研发 EMC 暗室改造；2025-12 报废两台老绕线机，2026-03 出售一辆旧商务车。
20. **伺服现场故障**：2025-11 至 2026-01 生产的伺服电机，编码器虚焊问题从 2025-12 起在客户现场集中暴露。售后看板按生产月统计的现场故障率明显高出一截，多数走先换后修，保内换新成本冲减质量保证金。2025 年末按实际索赔冲回多提的保证金后，2026 年索赔集中，余额不足，按月补提。这与 L5 良率下滑、编码器 Cpk 下降、编码器客诉是同一件事。2026-04 起，最早一批伺服陆续出保，开始出现保外付费维修。
21. **安全事故**：
    - 2025-06-17 冲压线 L8 压手损工 21 天，起因是光栅被短接；随后开展冲床安全专项检查，发现 2 项重大、4 项一般隐患。
    - 2025-12-09 旺季人车混行，叉车撞伤拣货员，损工 35 天；整改为人车分流和叉车蓝光警示。

## 智能问数与企业知识库

`assistant/` 里是两个 AI 服务（Python / FastAPI），前端入口分别是左侧菜单的「智能问数」和「企业知识库」：

- **经营与人力问数 Copilot**（端口 8093）：一句话查制度、查数据、问原因。规则路由 + Function Calling + SQL 安全校验 + 行级权限。文档见 `docs/Copilot-01` 到 `Copilot-04`。
- **企业知识库问答**（端口 8094）：规格书、手册、工艺文件、选型表、图纸统一入库；参数走 SQL、说明走向量检索、回答带出处。文档见 `docs/RAG-01` 到 `RAG-04`。

两个服务共用一套高并发保护和降级（限流、并发闸门、熔断、缓存）、RabbitMQ 批量任务、定时任务、告警中心（飞书 + 邮件）、Prometheus + Grafana 监控、Langfuse 链路追踪。

```bash
cd assistant && ./scripts/kbase.sh start      # 容器 + 两个服务 + 金蝶 EAS 模拟网关
```

早期的「技术助手」（端口 8090、8091）已于 2026-10-08 下线，由上面的企业知识库替代；本文和 `docs/` 里其他地方提到「技术助手」的内容都是历史说明。
