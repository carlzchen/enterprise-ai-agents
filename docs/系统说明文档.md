### 2.2 技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 后端语言与框架 | Java 21、Spring Boot 3.3.5 | Web、Data JPA、Validation、Security、AOP |
| 数据访问 | Spring Data JPA + JdbcTemplate | 简单实体用 JPA，报表和批量操作用 JdbcTemplate |
| 数据库 | MySQL 8.4（utf8mb4） | Flyway 管理结构，`ddl-auto: validate` |
| 认证 | Spring Security + JWT（jjwt） | BCrypt 密码，令牌有效期 12 小时 |
| API 文档 | springdoc-openapi 2.6 | `/swagger-ui.html`、`/v3/api-docs/minierp` |
| 日志 | SLF4J + Logback | 追踪号（traceId）写入 MDC，按天滚动 |
| 前端 | Vue 3、Vite、Element Plus、ECharts | 菜单和列表页由 `menu.js` 配置驱动 |
| 网关 | Nginx | 静态资源 + 反向代理 |
| 部署 | Docker Compose | MySQL、backend、frontend；技术助手的基础设施单独一套 compose |

### 2.3 后端分层与代码组织

```
com.minierp
├── common/        通用：业务异常、单号、SLA 计时 SlaClock、工作日历 WorkCalendar、TraceIdFilter、全局异常处理
├── security/      JWT 签发 / 校验、过滤器、账号状态缓存
├── system/        用户、审计日志（@Audited 切面）
├── query/         通用只读查询：白名单视图 ViewRegistry + 角色裁剪
├── masterdata/ plm/ sales/ crm/ purchase/ srm/ inventory/ wms/ transfer/ trace/
├── production/ aps/ mes/ eam/ quality/ qms/
├── gl/ finance/ fa/ treasury/ contract/ customs/ bi/
├── org/ workflow/ hr/ pm/ kb/
├── aftersales/ itsm/ ehs/ energy/
└── seed/          主数据目录 SeedCatalog + 逐日模拟器（BusinessSimulator 调度 Hr / Ops / Dev / Fin / Svc / Ehs / Plm 模拟）
```

**设计原则**

- **业务规则抽成纯函数类**：不依赖 Spring 和数据库，便于单元测试。例如 `CostMath`、`BomExploder`、`ApsScheduler`、`IncomeTaxCalculator`、`SpcCalculator`、`ExportRefundCalculator`、`TouTariff`。服务层只负责读写数据和编排。
- **业务事务内自动生成凭证**：先由 `VoucherValidator` 校验借贷平衡，不平衡则整笔业务回滚。
- **模块解耦**：流程结束时发布领域事件 `WorkflowFinishedEvent`，由报销、资本性支出、合同、IT 变更、作业票等业务模块各自监听处理。
- **只读查询统一走白名单视图**：不拼接 SQL，排序和过滤字段都做白名单校验。

| 数据 | 位置 | 备份方式 |
|---|---|---|

| 助手库 | 同一 MySQL 实例（库 `assistant`） | `mysqldump --databases assistant` |
| PLM 文档 | 卷 `plm-files` | 卷备份 |

### 3.5 重新生成模拟数据（标准流程）

1. 备份助手库：`mysqldump --databases assistant > assistant_backup.sql`
2. `docker compose stop backend`
3. 执行 `DROP DATABASE minierp; CREATE DATABASE minierp CHARACTER SET utf8mb4; GRANT ALL ON minierp.* TO 'minierp'@'%';`
4. `docker compose up -d --build backend frontend`，等待 "Seeding finished"
5. 在技术助手里强制同步知识库（`POST /kb/sync-kb?force=true`，因为知识库页面 ID 会变）

**验证建议**：先在临时库里跑，确认无误再动主库：

```bash
docker compose run -d --no-deps -e DB_NAME=minierp_smoke -e SEED_END=2025-03-31 -e PLM_STORAGE=/tmp/plm -e LOG_DIR=/tmp/logs backend
```

### 3.6 运维注意事项

- 用 mysql 命令行查中文时必须加 `--default-character-set=utf8mb4`，否则中文条件查不到数据。
- 已结账期间禁止记账。模拟器每月第一个工作日自动结上月账。结账前会校验：固定资产折旧已计提、增值税已月结、质量保证金已计提、试算平衡。
- 技术助手的 MCP 服务和查询服务是宿主机进程，不在 compose 里，机器重启后需要手动拉起。

## 4. 安全与权限

### 4.1 认证

- 用户名 + 密码（BCrypt）登录后签发 JWT，有效期 12 小时，请求头带 `Authorization: Bearer`。
- **离职即失效**：员工离职生效时停用账号。`JwtAuthFilter` 每次请求都检查账号是否仍启用（`UserStatusCache` 缓存 60 秒），所以旧令牌最多 60 秒后失效。
- 技术助手复用 ERP 的 JWT（HS256/384/512 都接受），不另建账号体系。

### 4.2 角色（RBAC）

| 角色 | 演示账号 | 权限要点 |
|---|---|---|
| ADMIN | admin | 全部功能、审计日志、IT 服务台处理 |
| MANAGEMENT | gm、cfo | 看板、报表只读；审批（总经理节点） |
| FINANCE | fin01 | 开票、收付款、凭证、月结、资金预算、增值税 |
| SALES | sales01 | 订单、客户、CRM、售后；**看不到成本和毛利字段** |
| PURCHASE | buyer01 | 采购、供应商、SRM |
| WAREHOUSE | wh01 | 发货、到货、调拨、库存调整、RMA 收货 |
| PRODUCTION | prod01 | 工单、报工、MES、APS、设备、安环 |
| QUALITY | qa01 | IQC、8D、SPC、OQC、RMA 检验、ECN 质量会签 |
| ENGINEER | eng01、eng02 | ECN、技术文档、NPI、研发项目 |
| HR | hr01 | 组织、员工、考勤、工资 |

演示密码统一为 `Demo@2026`，仅用于本地演示。

### 4.3 数据安全措施

| 措施 | 实现 |
|---|---|
| 接口鉴权 | 每个 Controller 用 `@PreAuthorize` 限定角色；写操作单独收紧 |
| 敏感列裁剪 | 通用查询按角色去掉成本、毛利、工资等列（`ViewRegistry.sensitiveCols`） |
| SQL 注入防护 | 通用查询的视图、过滤列、排序列都走白名单；分页有上限。业务 SQL 全部参数化 |
| 表达式注入防护 | OA 条件表达式由自研的 `ConditionEvaluator` 解析，不使用脚本引擎 |
| 职责分离 | 审批人不能审批本人提交的单据；ECN 申请人不能会签；报销审批不能是本人 |
| 审计 | `@Audited` 切面记录谁在何时做了什么（审计日志页面仅 ADMIN 可见） |
| AI 安全 | MCP 走网关模式，沿用调用者本人的 JWT 和角色；写类工具只生成草稿或发起申请，**不开放任何审批工具**。RAG 只做参数化 ERP 查询，不执行模型生成的 SQL；Milvus 过滤表达式做转义；MinerU 解压时校验路径，防目录穿越 |
| 密钥管理 | 密钥只放在 `assistant/.env`（gitignore、权限 600），日志不打印密钥；厂商 PDF 只放 `assistant/data/vendor/`（gitignore） |

## 5. 日志、追踪与可观测性

- **统一格式**：`时间 | 级别 | 追踪号 | 位置 - 消息`。Java 用 Logback，Python 用 loguru，两边格式一致。
- **全链路追踪号**：前端为每个请求生成 `X-Trace-Id`，后端、技术助手、MCP 都沿用并写进每一行日志，再通过响应头和错误响应体返回。用户报错时提供追踪号，运维直接 `grep` 就能找到这次请求在各系统的全部日志。
- **访问日志**：记录方法、路径、状态、耗时、用户；后端 ≥ 1 秒的慢请求记 WARN。
- **异常分级**：业务校验失败（`BizException`，返回 400）记 WARN，不打堆栈；系统异常记 ERROR，带堆栈；错误体为 JSON 且带 traceId。
- **文件**：后端 `logs/backend/minierp.log` 按天滚动（单文件 100MB、保留 14 天），`minierp-error.log` 只收 WARN 及以上（保留 30 天）；技术助手日志在 `assistant/logs/`。
- **业务层面的"监控"**：
  - 总账与子账对账页：存货、应收、应付、暂估、调拨在途、固定资产、累计折旧、其他应付、应收退税、应付职工薪酬、预计负债。
  - 银行余额调节表。
  - 月结前置校验。
  - WMS 库位库存与仓库现存量一致性校验。

## 6. 开放接口：REST / 通用查询 / MCP

### 6.1 REST API

- 交互文档：http://localhost:8080/swagger-ui.html；机器可读：`/v3/api-docs/minierp`（229 个接口，按模块分组）。
- 先 `POST /api/auth/login` 拿 token，之后带 `Authorization: Bearer <token>`。
- 各模块的主要路径：

| 模块 | 路径前缀 |
|---|---|
| 主数据 / 销售 / 采购 / 库存 | `/api/md`、`/api/sales`、`/api/purchase`、`/api/inventory`、`/api/transfers` |
| PLM / 研发 / 知识库 | `/api/plm`、`/api/pm`、`/api/kb` |
| 生产 / MES / APS / EAM / 质量 | `/api/production`、`/api/mes`、`/api/aps`、`/api/eam`、`/api/quality`、`/api/qms` |
| 财务 | `/api/gl`、`/api/finance`、`/api/fa`、`/api/treasury`、`/api/contracts`、`/api/customs` |
| 组织 / OA / HR | `/api/org`、`/api/oa`、`/api/hr` |
| 服务运营 | `/api/aftersales`、`/api/itsm`、`/api/ehs`、`/api/energy` |

### 6.2 通用只读查询

- `GET /api/views`：返回当前角色可访问的数据集目录，含中文说明、可过滤列、日期列，适合 Agent 自行发现数据。
- `GET /api/views/{key}?filter...&page&size&sort`：分页查询白名单视图。按角色裁剪敏感列，越权返回 403。
- 这是后续"财务经营分析 Agent"的主要数据入口，核心事实视图是 `v_sales_fact`。

### 6.3 MCP 服务（38 个工具）

## 7. 分系统说明

每个子系统按"定位 / 已满足需求 / 核心规则 / 主要数据 / 集成点"说明。

### 7.1 主数据

- **定位**：产品、物料（外购件 + 自制半成品）、BOM、客户、供应商、汇率、物料价格指数。
- **已满足需求**：
  - 产品有系列、事业部、功率、标准售价、加工费、经济批量。
  - 客户有行业、区域、币种、信用额度、账期。
  - 多级 BOM：成品 BOM `md_bom` + 半成品 BOM `md_material_bom`。
  - 替代料按优先级和替代比例配置（例如铜线换铜包铝，按重量折算）。
- **核心规则**：`BomExploder` 做逐层展开、同料合并、低阶码计算、循环引用检测；多级 BOM 展开页按树形展示每层用量、现存量和卷积成本。
- **集成点**：PLM 发布 ECN 时更新生产用 BOM；APS、MRP 按低阶码计算。

### 7.2 PLM（研发数据管理）

- **已满足需求**：
  - BOM 版本管理：A→B…，旧版本作废。
  - ECN 流程：草稿 → 四方会签（研发 / 生产 / 质量 / 采购，任一否决即否决）→ 批准 → 发布。发布前做影响分析（在制工单、库存、成本变化）。
  - 技术文档：规格书、图纸、SOP、检验标准、测试报告，带版本。
  - NPI 阶段门：概念 → 设计 → 样机 → 试产 → 量产，每个阶段门评审 GO / HOLD / KILL。
- **核心规则**：`BomChangeCalculator` 计算版本号与变更明细；申请人不能会签。
- **集成点**：
  - ECN 发布后自动生成知识库"设计变更说明"页。
  - NPI 立项自动建研发项目。
  - 规格书同步到 RAG。

### 7.3 销售与 CRM

- **已满足需求**：
  - 销售订单：草稿 → 确认（检查信用额度；超额的冻结在草稿）→ 发货（移动加权平均计成本）→ 开票 → 收款。
  - 多币种。
  - CRM：商机管道（逐级推进、丢单必须填原因）、跟进记录、客户联系人、漏斗统计。
- **核心规则**：`CreditPolicy` 检查信用额度；`WarehouseRouter` 发货选仓（前置仓整单有货就近发，否则从总仓发，避免拆单）。
- **集成点**：发货自动生成凭证；外销发货自动生成报关单；伺服序列号出货时按先进先出绑定发货单。

### 7.4 采购与 SRM

- **已满足需求**：
  - 采购流程：采购单 → 到货（待检）→ IQC → 合格入库 → 收票（三单匹配）→ 付款。
  - MRP：按"在制需求（展开到外购件）+ 10 天安全库存 − 库存 − 在途"生成采购单。
  - **应付暂估**：检验入库时贷记 220202，收到发票时冲回暂估、确认正式应付。
  - **采购价差**：价差 ≤ 3% 直接记账，> 3% 挂起等财务审批。价差按到货批次的在库比例拆分：在库部分调整存货成本（1403），已领用部分计入主营业务成本（6401）。这是实际成本法下的做法。
  - **SRM**：月度绩效 = IQC 合格率 50 分 + 准时交付率 30 分 + 价格指数 20 分；连续两个月 D 级自动转为"观察"。询价比价按综合评分推荐，选非推荐供应商必须填理由，定标后自动生成采购单。
- **核心规则**：`PriceVariance`、`SupplierScoring`。

### 7.5 库存、WMS 与多仓库调拨

- **已满足需求**：
  - 5 个仓库：原材料仓、半成品仓、成品总仓（深圳）、华东前置仓（苏州）、香港出口仓。每个仓库独立核算现存量和移动平均成本。
  - **批次追溯**：
    - 原材料批次号 = 到货单号，成品批次号 = 工单号，出库按先进先出消耗。
    - 反向追溯：客诉 → 成品批次 → 原材料批次 → 供应商 / IQC 结果。
    - 正向追溯：原材料批次 → 工单 → 发货单 → 客户，得到召回清单。
    - 多级 BOM 下可逐层展开追溯。
  - **调拨**：发出时 Dr 1402 调拨在途 / Cr 存货；到货时反向记账。批次随货转移（批次号、供应商、原入库日期不变），追溯链跨仓不断。
  - **前置仓补货**：订货点法，低于 7 天需求就补到 14 天（`ReplenishmentCalculator`）。
  - **WMS**：入库上架（同物料集中存放，新物料放最空的库位，`BinAllocator`），出库拣货（先拣零散库位）；Σ库位库存 = 仓库现存量，可一键校验。
- **核心规则**：`CostMath`（移动加权平均）、`LotAllocator`（先进先出）。

### 7.6 生产、APS 与 MES

- **生产**：
  - MPS 按"未发订单 + 安全库存 − 库存 − 在制"生成工单。
  - 组件工单按半成品低阶码逐层下达（伺服：转子铁芯 → 转子 / 定子组件 → 成品）。
  - 报工时按 BOM 倒冲领料，主料不足自动用替代料（`SubstituteAllocator`），报废损失摊入良品成本。
- **APS**：
  - 按低阶码分层排产。每层先做齐套检查：依次占用主料现存量 → 替代料现存量 → 主料在途 → 替代料在途，得到最早齐套日（`KittingCalculator`）。
  - 下层组件工单的计划完工日作为上层工单的"在途供应"，所以成品不会早于组件完工开工。
  - 有限产能按"单班产能 × 班次"计算，交期最早优先（EDD），缺料工单让位给已齐套的工单（`ApsScheduler`）。
  - 输出甘特图、负荷率，以及延期 / 缺料 / 替代料预警。
- **MES**：
  - 工艺路线：工序、标准工时、关键工序、检验点。
  - 班次结算：每条产线每天计算 OEE（时间开动率 × 性能开动率 × 合格品率，`OeeCalculator`）和劳动效率。
  - 伺服整机序列号 + 出厂测试（反电势、空载电流、编码器零位、绝缘电阻、振动），可单台追溯。
  - 首检 / 巡检（IPQC），不合格自动拉质量安灯；缺料停线自动拉缺料安灯；记录安灯响应和解决时长。
- **产线**：L1 罩极、L2 贯流、L3 无刷、L4 步进、L5 伺服、L6 减速，L7 伺服组件、L8 冲压叠片。

### 7.7 EAM 设备管理

- **已满足需求**：
  - 设备台账 47 台，每台有关键度和停机时损失产能的比例（瓶颈设备为 100%）。
  - 故障维修：报修（同时在产线拉设备安灯）→ 派工 → 完工；领用的备件出库，记入制造费用。
  - 预防性保养：按计划生成保养单，到期日自动顺延到工作日。
  - 可靠性指标：MTBF、MTTR、固有可用度（`ReliabilityCalculator`）。
- **集成点**：
  - 设备停机按损失比例压低当天产量，传导到交付和 OEE。
  - 同一设备一个月内故障两次及以上，自动沉淀为知识库故障案例。
  - 设备与固定资产卡片一一关联。

### 7.8 质量 QMS

- **已满足需求**：
  - IQC：抽样不良率 ≤ 2% 合格，否则整批判退。
  - 客诉：OPEN → ANALYZING → CLOSED，关闭前必须填写根因和纠正措施。
  - **8D**：中、高严重度客诉进入分析时自动开 8D，结案时补齐 D4–D8。
  - **SPC**：均值-极差控制图，计算 Cp / Cpk / Ppk，按 Western Electric 规则判异（`SpcCalculator`）。
  - **PFMEA**：计算 RPN、确定措施优先级，记录改进后的 RPN（`FmeaCalculator`）。
  - **量具校准**：到期提醒；不合格的停用报废。
  - **出货检验 OQC**：按 GB/T 2828.1 一般检验水平 II 正常一次抽样，含箭头规则（`AqlSampling`）。
- **集成点**：
  - 客诉进入分析时自动在研发项目生成缺陷，8D 结案时同步关闭。
  - 8D 结案沉淀为知识库页。
  - 中高严重度客诉自动开 RMA（见 7.19）。

### 7.9 财务总账 GL

- **已满足需求**：
  - **自动凭证**：发货、开票、收款、入库、收票、付款、报工、报销、调拨、折旧、工资、增值税、售后等业务都自动生成凭证。
  - 也支持手工凭证。报表有科目余额表、利润表。
  - **月结**：
    - 结账前校验：试算平衡、折旧已计提、增值税已月结、质量保证金已计提。
    - 结转制造费用差异到主营业务成本，结转损益到本年利润；12 月转入未分配利润。
    - 期间必须按顺序结账，已结期间禁止记账；反结账只能从最后一个已结期间开始。
  - **总账与子账对账**：1402、1403、1405、1411、1601、1602、1122、1221、2202、220202、2211、2241、2801。
  - 利润表：营业收入 = 主营 + 其他业务收入；营业成本同理；另列税金及附加、销售 / 管理 / 研发 / 财务费用、资产处置收益。
- **核心规则**：`VoucherValidator`（借贷平衡）、`ClosingCalculator`（损益结转）。
- **验证结果**：31,241 张凭证全部借贷平衡；24 个期间已结账；增值税各明细科目期末全部为 0。存货总账与子账差约万分之 0.2，来自移动平均单价的舍入。

### 7.10 固定资产

- **已满足需求**：
  - 期初约 80 项资产，包括房屋、设备（与设备台账关联）、模具、车辆、电子设备，并生成期初凭证。
  - 折旧（`DepreciationCalculator`）：年限平均法 / 双倍余额递减法（最后两年改直线法）；当月增加的次月起提，当月减少的当月照提；按"计划累计 − 已提累计"计算每月金额，舍入误差不累积。
  - 折旧按使用部门分别计入制造费用、销售费用、管理费用或研发费用。
  - **资本性支出（CAPEX）走 OA**：部门负责人 → 设备动力部（机器、模具类）→ 财务负责人 → 总经理（≥ 20 万）；审批通过后自动入账建卡。
  - 处置：通过 1606 固定资产清理结转，差额计入 6115 资产处置收益。

### 7.11 资金与预算

- **已满足需求**：
  - 银行账户与网银流水导入；利息、手续费等依据银行回单入账。
  - **银行对账**（`BankReconciler`）：先按"金额 + 附言（发票号）"匹配，最多容忍 31 天（覆盖长假，也能拆开同金额的两笔付款）；再按"金额 + 7 天"匹配。生成余额调节表和四类未达账项，采用截至期末口径。
  - 报销付款：每周五集中付款（Dr 2241 / Cr 1002）。
  - **13 周资金滚动预测**（`CashForecaster`）：应收按客户历史逾期天数推算回款日，应付按到期日，再加上工资、税款、退税；给出最低余额和低于安全余额的首周。
  - **预算控制**（`BudgetControl`）：按月、部门、费用类别编制预算。执行率 ≤ 90% 正常，90%–100% 预警，> 100% 超预算，报销流程自动加一个"超预算审批（总经理）"节点。

### 7.12 合同管理

- **已满足需求**：
  - 类型：销售框架、采购框架、服务、保密协议。
  - 流程：起草 → OA 审批（部门负责人 → 财务 ≥ 50 万 → 总经理 ≥ 200 万）→ 生效 → 到期（设了自动续约的顺延一年）。
  - 履约率：合同期内对该客户的开票额，或对该供应商的收票额，除以合同额。
  - 到期前 60 天进入提醒清单；年底按本年实际额乘以增长预期，签下一年的框架合同。

### 7.13 关务与增值税（出口退税）

- **已满足需求**：
  - 外销发货自动生成报关单，经放行、结关。HS 编码按产品系列和功率归类（`HsClassifier`）。
  - **增值税月结**按生产企业免抵退税计算（`ExportRefundCalculator`，财税〔2012〕39 号口径）：
    - 先算不得免征和抵扣税额，做进项转出；
    - 再算应纳税额、免抵退税额，拆成应退税额和免抵税额，剩余为期末留抵；
    - 各增值税明细科目结转到未交增值税（222105）；
    - 按"应纳 + 免抵税额"的 12% 计提城建税和教育费附加。
  - 次月 15 日缴纳增值税；出口退税款约 60 天后到账。

### 7.14 组织与统一身份

- **已满足需求**：
  - 部门树 16 个（第五批新增客户服务部、安全环保部），每个部门有成本类型，决定人工成本进哪个费用科目。
  - 岗位职级、员工档案，以及入职、转正、调岗、调薪、离职的异动记录。
  - 账号挂在员工上，员工离职自动停用账号。
  - 汇报关系由 `OrgChart` 计算：档案里指定了直属上级就用它，没有就取部门负责人；本人就是负责人时向上找。

### 7.15 OA 流程引擎（自研）

- **已满足需求**：
  - 流程定义用 JSON 描述节点，按版本管理，运行中的实例按发起时的版本执行。
  - 审批人类型：直属上级（可指定第几级）、申请人部门负责人、指定部门负责人、角色、指定账号。
  - 每个节点可设或签 / 会签和进入条件，例如 `amount >= 5000 && days > 3 || leaveType == 'SICK'`。
  - 发起时算出整条审批路线：条件不满足的节点跳过，申请人本人跳过，前序已审批过的人去重（`WorkflowRouter`）。
  - 办理操作：同意、驳回（必须填理由）、转交、加签、撤回（还没人同意时才能撤回）。
  - 前端：审批中心（待办 / 已办 / 我发起的）、路线步骤条、审批时间线、流程定义编辑。
- **内置 11 个流程**：

| 编码 | 名称 | 路线要点 |
|---|---|---|
| LEAVE | 请假 | 直属上级 → 部门负责人（≥3 天）→ HR（≥5 天或病假） |
| EXPENSE | 费用报销 | 直属上级 → 部门负责人（≥5000）→ 财务 → 总经理（≥5 万）→ 超预算审批 |
| CAPEX | 资本性支出 | 部门负责人 → 设备动力部（机器、模具类）→ 财务负责人 → 总经理（≥20 万） |
| CONTRACT | 合同审批 | 部门负责人 → 财务（≥50 万）→ 总经理（≥200 万） |
| IT_CHANGE | IT 变更 | 信息部负责人 → 总经理（高风险） |
| EHS_PERMIT | 危险作业许可 | 部门负责人 → 安环部 → 总经理（受限空间或一级动火） |
| TRAVEL / SEAL / RESIGN / PAYROLL / GENERAL | 出差 / 用印 / 离职 / 工资发放 / 通用审批 | — |

- **集成方式**：流程结束时在同一事务内发布 `WorkflowFinishedEvent`，由业务模块完成后续动作：报销入账、请假写考勤、资本性支出建卡、合同生效、变更批准、作业票批准。

### 7.16 HR 与薪酬

- **已满足需求**：
  - 考勤日记录（正常 / 迟到 / 旷工 / 请假，含加班）；请假审批通过后自动写入考勤。
  - **计件工资**：各产线单价按报工日期取有效单价，只计良品；班组当月计件总额按组员出勤工时分摊，用最大余数法处理分摊尾差（`PieceWageAllocator`）。
  - **月度工资**（`PayrollCalculator`）：
    - 月薪按在职天数折算，扣事假和旷工；
    - 计件不足保底的按出勤补足；加班产量已计件，只另付 0.5 倍溢价；
    - 社保公积金按缴费基数上下限计算；
    - 个税用累计预扣法（`IncomeTaxCalculator`）。
  - 工资发放审批通过后计提入账，按部门成本类型进入制造费用或期间费用；次月 10 日发放并代扣代缴个税。
  - HR 看板：人数、入离职、流失率、出勤率、人工成本、人均工资、加班。

### 7.17 研发项目管理（类 Jira）

- **已满足需求**：
  - 项目（SCRUM / KANBAN）、迭代、问题（史诗 / 需求 / 任务 / 缺陷）、评论、工时、问题关联；看板支持拖拽。
  - 状态流转由 `IssueWorkflow` 校验，例如需求和缺陷必须经过评审才能完成，史诗下还有未完成的问题时不能关闭。
  - 所有变化写入历史表。燃尽图、速率与预测区间、周期时间 p50 / p85 / p95、累积流图都从历史表计算（`AgileMetrics`）。
  - **研发费用按项目归集**（`RndCostAllocator`）：研发人员人工成本按项目工时 ÷ 出勤工时分摊，形成研发费用加计扣除的项目辅助账。
- **集成点**：NPI 立项自动建项目；客诉自动生成缺陷，8D 结案时同步关闭。

### 7.19 售后服务（第五批）

- **定位**：客户服务中心，处理保修查询、服务工单、退换货和质量保证金。
- **已满足需求**：
  - **保修查询**（`WarrantyPolicy`）：输入伺服序列号，带出产品、生产工单、出厂测试结果、客户、发货日期、保修到期日、是否在保、历史工单。保修期为伺服 18 个月、其他产品 12 个月，自发货日起算。
  - **服务工单**：类型分故障 / 技术咨询 / 安装调试；渠道分电话 / 微信 / 邮件 / 门户。处理方式分远程、上门（产生差旅报销）、返厂、无故障。关闭时做满意度评价。
  - **SLA**（`SlaClock`）：

    | 优先级 | 计时方式 | 响应 | 解决 |
    |---|---|---|---|
    | P1 客户停线 | 7×24 | 2 小时 | 24 小时 |
    | P2 | 工作时间 | 4 小时 | 24 小时 |
    | P3 | 工作时间 | 8 小时 | 40 小时 |

    工作时间指工作日 8:30–17:30，跳过周末和法定节假日。
  - **RMA 退换货**：
    - 两个来源：单台工单（先换后修，开出 RMA 即算工单解决）、中高严重度客诉（批量退回）。
    - 处置方式：
      - 换新：成品出库。成品库存不足退货量 3 倍时改为维修，避免挤占正常发货。
      - 维修：按故障类型领用 BOM 中的对应部件（异响换轴承、编码器故障换编码器……）。
      - 无故障：原样退回。
    - 严重客诉另有客户索赔（停线损失、挑选返工费），通过银行支付。
  - **质量保证金**（预计负债 2801）：
    - 期初 30 万，每月按主营收入 × 计提比例计提；
    - 保内成本和客户索赔冲减保证金；
    - 年末按"近 12 个月索赔 ÷ 12 × 在保平均剩余月数"测算应有余额，补提或冲回，并确定下年计提比例（索赔率 × 1.1，限定在 0.05%–3%）；
    - 上线不足 12 个月不调整；月末余额低于近 3 个月索赔额时补提差额，保证预计负债不出现借方余额。
  - **保外付费维修**：收取服务费（Dr 1002 / Cr 6051 其他业务收入 + 222102 销项税），耗用部件计 6402 其他业务成本。
- **看板**：
  - 工单量、SLA 达成率、平均响应 / 解决时长、一次修复率、满意度；
  - RMA 与保内成本、保证金余额与计提比例；
  - 伺服按生产月的现场故障率（每千台），可以定位批次问题；
  - 故障类型、服务工程师工作量。
- **近 12 个月实际数据**：793 张工单，SLA 达成率 94.3%，满意度 4.57，RMA 299 单 / 1,030 台。

### 7.20 IT 服务台（第五批，ITIL 简化版）

- **已满足需求**：
  - **故障与服务请求**：任何员工都能提交。优先级由"影响范围 × 紧急程度"矩阵决定（`PriorityMatrix`）：

    |  | 紧急高 | 紧急中 | 紧急低 |
    |---|---|---|---|
    | 影响高（全厂 / 产线） | P1 | P2 | P3 |
    | 影响中（一个部门） | P2 | P3 | P4 |
    | 影响低（个人） | P3 | P4 | P4 |

    SLA：P1 按 7×24 计时，响应 0.5 小时、解决 4 小时；P2 为 1 / 8 小时，P3 为 4 / 24 小时，P4 为 8 / 40 小时，均按工作时间计。
  - **变更管理**：走 OA 流程 IT_CHANGE，高风险变更需总经理审批；批准后实施、关闭，可以关联引发它的故障（重大故障 → 根因 → 变更）。每月补丁、每季度 ERP 发版都走变更。
  - **CMDB**：服务器、网络设备、打印机、MES 终端、每位职员的笔记本，与员工、部门、固定资产卡片关联；标记重要性，统计在用超过 4 年的设备。
  - **入离职联动**：
    - 入职：自动开服务请求，领用库存笔记本，分配全员许可和部门许可；席位不足时记在工单里。
    - 离职：回收电脑（满 4 年报废），释放许可，停用账号。
  - **软件许可合规**：全员许可按在职人数对比席位，部门许可按入职时未分配到的申请统计缺口；许可到期续费走报销。
- **看板**：故障 / 请求 / 变更数量、SLA 达成率、MTTR、按优先级与分类统计、重大故障及关联变更、故障最多的配置项、CMDB 汇总、许可状态。
- **近 12 个月实际数据**：870 张工单，SLA 达成率 93.4%，满意度 4.67。

### 7.21 安全环保 EHS（第五批）

- **已满足需求**：
  - **隐患排查治理**：来源有周检、员工随手拍、专项检查、事故整改。一般隐患 7 天、重大隐患 30 天整改，整改后由安环部复查，不通过的重新整改。统计按期整改率和逾期情况。
  - **事故与未遂事件**：按海因里希金字塔分为未遂、急救、可记录、损工四级。可记录和损工事故必须填写根因与整改措施才能关闭。
  - **安全绩效**（`EhsRules`，工时取自考勤）：
    - LTIFR（百万工时损工事故率）= 损工事故数 × 10⁶ ÷ 工时
    - TRIR（可记录事故率）= 可记录事故数 × 2×10⁵ ÷ 工时（OSHA 口径）
    - 严重率 = 损失工日 × 10⁶ ÷ 工时
    - 另统计无损工事故天数。
  - **危险作业许可**：动火（一级 / 二级）、高处、受限空间、临时用电，走 OA 流程 EHS_PERMIT，设监护人，作业结束后关闭作业票。
  - **危险废物台账**：HW08 废矿物油、HW12 浸漆废物、HW49 含油抹布 / 包装桶。按月登记产生，按季度转移（生成联单号，处置费走报销）。按先进先出计算最早一批的贮存天数，超过 270 天预警，超过 365 天违规（固废法规定贮存不得超过一年）。
- **全期实际数据**：LTIFR 1.14，TRIR 0.46；发现隐患 518 项（重大 17 项），按期整改率 89%。

### 7.22 能源管理（第五批）

- **已满足需求**：
  - **电表**：8 条产线、空压站、中央空调、伺服老化房、办公研发楼、宿舍。按日读数，分尖 / 峰 / 平 / 谷各时段。
  - **分时电价**（`TouTariff`，广东工商业口径）：
    - 峰段 10–12、14–19 点，谷段 0–8 点，其余为平段；
    - 峰平谷比价 1.7 : 1 : 0.38；

- **规模**：年用电约 730 万 kWh，月电费约 50–65 万元，综合电价约 0.78–0.84 元/kWh。

## 12. 已知限制与后续计划

### 12.1 已知限制

| 项 | 说明 |
|---|---|
| 成本方法 | 实际成本法（移动加权平均），没有标准成本和差异分析（价格差异 / 用量差异） |
| APS 与 MRP | 组件工单由 MRP 下达、APS 只排程，两者还没合并为一次计算 |
| 存货对账尾差 | 移动平均单价舍入导致约万分之 0.2 的差异（页面上会显示） |
| 软件许可 | 模拟里专业软件席位没有自动增购，所以许可看板显示缺口（这是真实的待办） |
| 多组织 | 单法人、单账簿；没有多公司合并报表 |
| 高可用 | 单机 Docker Compose 部署，没有集群、读写分离和缓存层（ERP 侧） |
| 监控告警 | 有日志和追踪号，但没有接 Prometheus / Grafana，也没有告警 |
| 技术助手进程 | 宿主机进程，不在 compose 里，重启后需要手动拉起 |
| 前端 | 没有做移动端适配和国际化 |

### 12.2 后续计划

1. ~~财务经营分析 Agent~~：已作为"经营与人力数据分析 Copilot"实现，见 7.25。还没做的部分：阈值预警订阅、Excel 台账解析、制度与个人数据的混合问答。
2. 标准成本与差异分析。
3. APS 与 MRP 合并为一次计算，直接生成计划订单。
4. 可观测性：接入 Prometheus + Grafana，业务指标（对账差异、SLA 违约、结账失败）配置告警。
5. 技术助手服务容器化，并入统一 compose。

## 13. 附录：常用命令

```bash
# 服务状态与日志
docker compose ps
docker compose logs -f backend
grep <traceId> logs/backend/minierp.log assistant/logs/*.log

# 单元测试
cd backend && docker run --rm -v "$PWD":/app -v minierp-m2:/root/.m2 -w /app maven:3.9-eclipse-temurin-21 mvn -o test

# 进入数据库（中文必须加字符集）
docker exec -it $(docker compose ps -q mysql) mysql -uroot -proot --default-character-set=utf8mb4 minierp

# 备份
docker exec $(docker compose ps -q mysql) mysqldump -uroot -proot --databases minierp assistant > backup.sql

# 接口文档
open http://localhost:8080/swagger-ui.html

# 技术助手与 MCP
cd assistant && uv run python main.py
uv run python -m app.api.mcp.erp_mcp_server              # http://127.0.0.1:8092/mcp
uv run python -m app.api.mcp.erp_mcp_server --transport stdio
```
